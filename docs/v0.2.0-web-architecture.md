# v0.2.0 Web Architecture — API Contract

> Status: **draft for the v0.2.0 Tauri-removal refactor.**
> Audience: the four parallel coders (HTTP server, web client, e2e, docs) — every track
> reads this file before starting.

## Goal

Remove the Tauri shell entirely. The web client (Vite + React) talks to the Python agent
over HTTP + WebSocket, like a normal SPA + JSON API. The agent runs as a regular Python
process bound to `localhost:<port>`. No native shell, no packaging, no sidecar.

## Endpoints

The agent binds `127.0.0.1:<port>` (default **8765**, override with `--http-port` CLI arg
or `MINIMAX_CODE_HTTP_PORT` env). All routes are relative to that.

| Method | Path                    | Purpose                                                |
|--------|-------------------------|--------------------------------------------------------|
| GET    | `/health`               | Liveness probe — `{"ok": true, "version": "0.2.0"}`    |
| POST   | `/rpc`                  | JSON-RPC 2.0 request → response (one shot)             |
| GET    | `/ws`                   | WebSocket: server-push events (chunks, progress, etc.) |
| GET    | `/events` (alt for SSE) | Server-Sent Events fallback (if WebSocket unavailable) |

### `POST /rpc`

Body — JSON-RPC 2.0 envelope (same shape as today's stdio protocol):

```json
{
  "jsonrpc": "2.0",
  "id": "uuid-or-client-counter",
  "method": "session.list",
  "params": { "archived": false, "limit": 50, "offset": 0 }
}
```

Response on success:

```json
{
  "jsonrpc": "2.0",
  "id": "<same id>",
  "result": { "sessions": [...] }
}
```

Response on error:

```json
{
  "jsonrpc": "2.0",
  "id": "<same id>",
  "error": { "code": -32601, "message": "unknown method: foo.bar" }
}
```

Standard JSON-RPC error codes (use the existing ones in `agent/minimax_code/ipc/protocol.py`).

HTTP status: always `200` — the JSON-RPC error envelope carries the failure. (A 500 is reserved
for "agent itself crashed" or "request couldn't be deserialized".)

### `GET /ws`

WebSocket upgrade. After connecting, the server immediately starts pushing server-side events.
Each event is one JSON-encoded JSON-RPC 2.0 envelope with no `id` and an `event` field:

```json
{
  "jsonrpc": "2.0",
  "method": "agent.message_chunk",
  "params": { "session_id": "...", "message_id": "...", "delta": "Hello", "done": false }
}
```

The `method` field carries the event name (mirroring today's Tauri `EVENT_NAME = "ipc:event"` push
events). `params` is the event payload. The same set of stream events the Tauri shell delivered
goes through this socket: `agent.message_chunk`, `agent.status`, `agent.tool_call`,
`agent.tool_result`, `agent.permission_request`, `agent.permission_resolved`, `task.progress`,
etc.

The server also pushes lifecycle events on the socket:
- On connect: server sends `{"method": "agent.ready", "params": {"server": "minimax-code-agent", "version": "0.2.0"}}` once the runtime is up.
- On agent shutdown: server closes the socket cleanly.

### `GET /health`

Returns `{"ok": true, "version": "<agent version>", "uptime_s": <int>}` as long as the agent
process is alive. Used by the web client for the "is the agent running?" badge.

## Request routing (server side)

The agent already has a stdio JSON-RPC server in `agent/minimax_code/ipc/server.py`. It owns a
registry of handlers (`agent.*`, `skill.*`, `task.*`, `session.*`, `mobile.*`, `permission.*`,
`schedule.*`, `model.*`, `secrets.*`, plus internal `system.*` / `__init__.*` etc). The HTTP server
should **reuse that registry**, not build a parallel one:

1. On startup: `register_app_handlers(server)` (already in `agent/minimax_code/app.py`).
2. The HTTP server holds a reference to the same `IPCServer` (or shares its `HandlerRegistry`).
3. A POST `/rpc` deserializes the envelope, calls `server.handle_request(env)`, awaits the
   `Awaitable[Envelope]`, and serializes the response.

Concretely, refactor `IPCServer` so the per-request method is callable directly (it already is —
`server.handle_request` is the method). The HTTP server is a thin transport.

For events: the existing IPC server pushes events to its `stdout`. We add an optional **in-process
subscriber list** to `IPCServer` — `register_listener(callback)` — so the HTTP server can subscribe
and forward each event to all open WebSocket connections. This is cleaner than parsing stdout.

> Implementation hint: add a `listeners: list[Callable[[Envelope], None]]` field on
> `IPCServer`, a `register_listener` method, and a `notify(event_envelope)` method that calls
> each listener. Refactor the existing `write_event` / `emit` to call `notify` internally.
> The stdio server writes to stdout AND notifies (so the listener chain is observable from
> HTTP without changing stdio behavior for CLI users).

## CORS

Allow-list: `http://localhost:5173` (Vite dev) and `http://127.0.0.1:5173` only. Tight CORS is
fine — this is local-only. Production-style CORS isn't a concern for an internal tool.

## Auth

**None for v0.2.0.** Local-only, single-user, binds to `127.0.0.1` so other machines on the LAN
can't connect. When the user wants multi-user or remote, add a token check then.

## Environment

| Var                          | Default       | Purpose                                       |
|------------------------------|---------------|-----------------------------------------------|
| `MINIMAX_CODE_HTTP_PORT`     | `8765`        | TCP port for HTTP + WS                        |
| `MINIMAX_CODE_HTTP_HOST`     | `127.0.0.1`   | Bind address (NEVER `0.0.0.0` in v0.2.0)      |
| `MINIMAX_CODE_DATA_DIR`      | platformdirs  | Storage / DB location (unchanged from v0.1.x) |
| `MINIMAX_CODE_API_KEY`       | (env or keyring) | LLM client key (unchanged)                  |

CLI:

```bash
# New: start as HTTP server (default mode in v0.2.0)
python -m minimax_code                     # binds 127.0.0.1:8765
python -m minimax_code --http-port 9000    # override port

# Stdio mode is preserved for tests and CLI debugging:
python -m minimax_code --stdio             # old JSON-RPC over stdio
```

When `--stdio` is passed, the existing stdio server runs. When omitted, the HTTP server runs.
Don't run both at once in a single process — they share the handler registry and event
listeners, so dual-mode would interleave stdout writes with HTTP responses.

## Web client API (TypeScript shape)

The new `IPCClient` in `web/src/ipc/client.ts` MUST preserve the same `TypedIPC` interface
(`ping`, `listSessions`, `createSession`, `sendMessage`, `listModels`, etc.) so the React stores
need zero changes. Implementation details swap, public surface stays.

Internally:

- `IPCClient.useMock` — if `process.env.NEXT_PUBLIC_AGENT_MODE === "mock"` OR (default) the
  HTTP `/health` probe returns non-OK within 200 ms, fall back to the existing in-process mock
  backend (the `mockHandle` switch in client.ts).
- `IPCClient.request<T>(method, params)` — fetch POST to `/rpc`, return `result`.
- `IPCClient.on(event, cb)` — subscribe via the WebSocket; reconnect on close with exponential
  backoff (250ms → 500ms → 1s → 2s, cap at 5s).
- `IPCClient.ping()` — fetch GET `/health`.

The `Mock` backend (the big `mockHandle` switch) **stays** as the offline / Vitest fallback.

## Build / dev workflow

Two terminals (down from three in Tauri mode):

```bash
# Terminal 1 — agent
cd agent
uv run python -m minimax_code
#  → "agent server listening on http://127.0.0.1:8765"

# Terminal 2 — web
pnpm dev
#  → vite ready, open http://localhost:5173
```

`pnpm dev` stays a single command that spawns Vite (and optionally the agent via the existing
`scripts/dev.mjs`). The agent-launch script is updated to use the new HTTP entry point.

## What gets deleted

The team will delete the following as part of the refactor:

- `src-tauri/` — entire directory (Rust code, Cargo.toml, tauri.conf.json, icons, target/)
- `scripts/gen_tauri_icons.py` — no longer needed
- `src-tauri` references in `.gitignore`, `docs/`, root `package.json`
- `@tauri-apps/api`, `@tauri-apps/cli` from `web/package.json` + root `package.json`
- `tauri:dev`, `tauri:build`, `tauri` scripts from `package.json`
- The `Desktop` references in `docs/architecture.md` — replace with the new web-server topology
- Tauri-only entry from `CHANGELOG.md` (the v0.1.x packaging saga)
- `v0.1.0` / `v0.1.1` / `v0.1.2` / `v0.1.3` tags — keep `v0.1.3` as a reference of "this is what
  the Tauri build produced" but don't reference it in the new README. (We can keep the tags
  in git history for archival; the user can `git tag -d` them later if they want.)

## What stays

- `agent/` — all Python code, all DAOs, all IPC handlers, the stdio server (still used for tests)
- `web/` — all React code, all stores, all components. Just `web/src/ipc/client.ts` changes.
- `tests/` — all 7 black-box subprocess smokes. The agent's stdio server is still the test
  target, so these stay valid. **The smokes are now also the contract test for the HTTP server's
  request routing** (a future smoke can do the same flow over HTTP and assert identical results).
- `docs/` — `ipc-contract.md` updates the "transport" line from "stdio JSON-RPC 2.0" to
  "HTTP JSON-RPC 2.0 + WebSocket events".

## What changes for the user

- No more MSI/NSIS to install. Run two commands in two terminals.
- Hot reload still works (`pnpm dev` is the same).
- The agent's API key handling is unchanged: OS keyring first, `MINIMAX_CODE_API_KEY` env fallback.
- v0.1.0 / v0.1.1 / v0.1.2 / v0.1.3 install files: kept on disk in `src-tauri/target/release/bundle/`
  for archival, no longer referenced by the docs.
