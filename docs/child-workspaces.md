# 子 Agent 独立工作副本

M1 默认真实子任务在 `<父工作区>/.minimax/child-workspaces/<run_id>/workspace`
执行。工具、RPC、团队成员共享 `SubAgentRuntime.invoke` 边界。Git 项目创建
detached worktree，复制当前工作目录内容，保留父目录已有的暂存、未暂存和未跟踪
文件状态；非 Git 项目使用独立目录。准备失败会停止运行，不回退共享目录。

这是工作区隔离，用于避免正常相对路径写入互相覆盖，不是操作系统沙盒。
宿主机命令仍属于受信执行；Linux 容器限制在 M5 另行实现。

## 执行、收取和恢复

- `manifest.json` 保存父目录、run ID、输入哈希、运行状态及结束后的文件哈希。
  完成报告仍保存在父目录的运行产物位置；查询结果包含 `workspace` 和变更文件。
- `collect_subagent` 显式收取新增和修改的文件，先检查父目录是否发生同期变化。
  默认遇到冲突不应用任何文件；`skip` 只处理不冲突文件，并保持未完成状态。
- 替换前备份位于该 run 的 `backups/`，写入使用原子替换和基线校验。成功回执
  保存后可重复查询；收取后保留工作副本和备份，不自动清理。
- 删除文件、目录/文件类型变化、符号链接/目录联接、结束后继续变化的子目录内容
  需要核对。当前自动收取仅处理文件内容新增/修改，不声称支持精确撤销或完整 Git
  索引合并。文件权限、重命名和删除的完整交付流程仍须继续实现。
- 取消会等待内部 invoke 结束再注销运行；墙钟超时先给 5 秒协作退出时间，随后
  取消内部任务。失败、取消和准备失败保留工作副本。服务重启后遗留 `running`
  不可直接收取，需后续 RunService 恢复流程核对。

## 输入与容量边界

默认最多 10,000 个文件、总计 128 MiB、单文件 16 MiB，超限报错。Git 项目只复制
跟踪文件和未被忽略的未跟踪文件；非 Git 项目遍历普通文件。依赖、缓存、构建输出、
`.git`、`.minimax`、`.ssh`、以 `.env` 开头的路径、`.pem`/`.key` 文件不复制。
Git 项目被这类规则省略的条目列在 `workspace.omitted`。这是避免复制常见本地
配置的规则，不是秘密识别器；普通源码仍由用户选择的模型处理。

依赖目录不共享写挂载；子任务需要验证时应在自己的目录准备依赖。尚未产生提交的
Git 仓库无法创建 detached worktree，当前会明确报错。后续可增加受控目录模式，
但不能静默切换回父目录。

## 数据兼容与回退

无数据库 schema 变化；新字段为可选结果元数据，旧 mock 不伪造文件系统。
保留旧版显式 `sandbox=true` 文件 overlay，其 shell 禁令继续生效。
回退代码前应先停止子任务并记录未收取副本。旧代码不能收取新格式副本，需保留
目录、manifest 和备份，用支持该格式的版本核对；不要以回退为由删除用户结果。
Git worktree 清理应先检查未提交内容，再通过 Git 的工作树移除流程处理。

本批离线测试包含真实 Git、真实本地 Python 子进程和受控模型对象，不代表真实模型
任务集或 Linux 容器验收通过。
