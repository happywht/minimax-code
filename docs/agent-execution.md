# Durable Native agent execution

Public agent invocation uses the same RunService, AgentCore, permission gate and budget boundary as Native tasks. It does not call SubAgentRuntime to wrap a second execution loop. Team roots remain outside this batch.

## Request and receipt

Both `agent.invoke` and `agent.spawn_subagent` require an existing explicit Native source session, a stable idempotency_key, a nonempty string request and required name (a registry name or legacy ID); agent_id is an optional compatibility identity. The frontend saves the complete intent and key before sending. Retry an uncertain admission with the same intent/key; a changed intent conflicts. Replay precedes current registry/model resolution, so deleting a configuration does not erase an already admitted receipt.

The source session is provenance. Admission creates a separate execution session and durable run, avoiding a parent session lease waiting on its own child. Client run_id is only a compatibility association; the server allocates the durable ID. Public roots each receive a new cumulative budget family. Only trusted tool descendants inherit their actual parent's family and parent_run_id. Public parameters cannot inject instructions, tools, family or internal execution profiles.

Waiting replies retain agent/text/agent_run_id and add durable run_id, execution session_id, run_status, partial flags and workspace evidence. The complete receipt is saved before terminal completion; run queries and replay read that saved result. Admission-only calls return the existing run/created envelope. Cancellation acknowledges a request and observed status; it does not claim descendant processes have stopped. The UI refreshes the real terminal result and can open the execution session's timeline.

## Frozen profile and supported configurations

The server resolves an AgentExecutionSpec containing registry identity, copied instructions, tool schema/provider identity, model/provider fingerprint, source directory identity, reserved copy identity, permission snapshot, iteration/temperature settings and result version. Secrets and plaintext provider endpoints are not added to run metadata. A private client and deep-copied private tool registry serve each root. Queued instructions/model/tool selection remain fixed; current disablement, missing or changed providers, tool identity drift and permission revocations still fail closed. Permissions at use are the intersection of admitted and current policy, never a grant from an old snapshot.

The configured agent model or explicit request model must belong to the already verified selected provider route. Unsupported model/provider combinations refuse before preparation or SDK sends. Trusted descendants may select only models captured as verified on that same route. Ordered skills declarations now contribute full frozen Skill instructions (including applicability and version headers) and selected private provider tools to this same Agent root. Exact composite IDs take priority; short names must resolve uniquely. Unknown, ambiguous, duplicate canonical IDs and disabled dependencies refuse before root admission/preparation/SDK. Older code merely passed this field through; this batch implements its execution semantics without an additional skill loop, client or family.

Agent tool_allowlist is applied after building baseline tools plus the selected private providers. None freezes the complete candidate set; [] permits no business tools and conflicts with any skill requiring tools. An explicit list must contain only available names and include every selected skill's manifest requirements. Provider extra exports are recorded but do not override that list. Baseline/provider and provider/provider tool name collisions are refused. The manifest is a requirement list, never an exhaustive allowlist. code-review mounted this way remains a generic Agent result; it does not invent structured review findings or choose the diff-specific result adapter.

AgentExecutionSpec v2 stores bindings schema v1: ordered canonical IDs, declared versions, complete frozen instructions, manifest requirements, actual provider exports and provider/class/schema fingerprints. Same-version text edits retain the accepted text. Before queued execution, reviewed resume or continue, current canonical declarations, dependency availability/version/manifest/provider identities and model route are rechecked. Current allowlist removals refuse the saved capability; additions do not expand it. The known no-skills v1 branch retains its saved tool set and permission format while also honoring current revocations; v2 missing/damaged bindings refuse and cannot become generic chat. B1 SkillExecutionSpec v1 is unchanged. This is a JSON metadata change with no SQL migration.

Trusted internal children use the same bindings resolver before durable child admission, save bindings/effective tools with that run, and revalidate before their first send. Their business/provider tools cannot exceed the actual parent registry. Missing required skill tools cause a child configuration failure, never silent removal or a global-registry fallback. Actual inherited provider tools also retain their dependency fingerprints even when the child declares no skills; current dependency revocation therefore cannot be lost through an empty list. Inherited provenance does not inject parent skill text. Each child keeps its own frozen skill text and private tool instances; recursion preserves the existing family, durable owner and retained descendant lifetime. Two existing runtime receipt channels are separate: trusted server constructors bind report_completion/report_progress to the current child only. Providers cannot use these reserved names, and grandchildren receive fresh bindings to their own runs. These channels grant no file/process business capability; a self-reported completed report does not override durable terminal/verification evidence.

Settings supports ordered skill IDs/names on create/edit, including an explicit empty list to remove them. Reopening the mention picker refreshes current configurations and discards responses from a closed picker, so a just-configured Agent can be invoked without reloading the app. Public request keys, source/execution sessions, copy ownership and cumulative budget behavior are unchanged.

Agent tool_allowlist remains its configured tool set. Runtime analyzers and shell/test tools use the normal ExecutionPolicy and permission gate; an independent working copy is not an OS security sandbox or a read-only review guarantee. Skill execution retains its separate baseline-tools-plus-selected-provider contract.

## Admission, copy ownership and recovery

One SQLite transaction creates the source/key mapping, independent execution session, queued run, budget family and initial event. Allocation itself creates no directories. Only the created RunService owner, while holding the execution session lease, prepares the single copy and saves its actual identity and session binding before AgentCore runs. Source directory replacement or binding changes refuse. Failed admission rolls back all rows; submit failure retains the same durable run. Preparation failure or cancellation never silently retries a second copy.

Git roots use detached worktrees; other roots use owned directory copies. Parallel agents writing the same filename cannot modify the source or each other's copies. Results retain collection/review evidence; publication/merge is a separate action. Recursive retained ownership drains children and newly registered cleanup descendants before private client, gate and lease close. Double cancellation cannot abandon process termination. Every governed child attempt joins its own durable run/session and the shared family. This launch check is not a new global budget-attempt foreign-key guarantee.

Preliminary receipts survive final persistence faults. An unconfirmed terminal write cannot be reported as a successful waiting call. Child admission refusal prevents that child's launch; child terminal persistence failure cannot count as child success. Existing shared budget settlement quarantine remains the separate mechanism that blocks subsequent paid sends on accounting persistence failure.

Startup recovery performs a pure saved-receipt projection to interrupted without live registry/model lookup or execution. A pending/unconfirmed copy cannot resume automatically: inspect retained files and start a new task. Prepared copies can resume only after explicit review, identity validation and budget accounting reconciliation where required. Saved profile/copy and cumulative family persist through recovery/continue. Missing, replaced or ambiguous copies, unsupported dependencies and absent profiles cannot fall back to generic chat or the process cwd. Unknown attempts retain liability; increasing a cap does not clear them. No unknown writes replay automatically.

The UI retains stable keys and run IDs through reload. Delayed responses use identity checks before replacing state or navigating sessions. Cancellation, budget_paused, interrupted and partial/failed dimensions stay distinct from a completed full result. Frontend-only mock receipts share request validation and replay semantics, but do not prove filesystem/process isolation.

## Verification and rollback

Offline verification used actual handlers, controlled SDK HTTP transport, AgentCore, SQLite and real OS child processes; no paid model calls were made. The final source freeze is based on bc423c0 with 36 owned paths. Completed evidence:

- Backend: 1177 passed in 341.97 seconds, exit 0. The exact 63-module selection is `.verification/b2a-backend-selector-final.txt`; completed output and exit marker are `b2a-backend-frozen-final.log` and `.exit`. This includes recursive durable ownership, independent writes, duplicate/lost-ACK admission, two-connection atomicity, startup/reviewed recovery, unknown liabilities, repeated cancellation during process cleanup and preparation, and admission/preliminary/final storage refusal.
- Frontend: 848 tests across 108 files passed in 47.52 seconds, exit 0 (`b2a-web-final.log`). TypeScript, ESLint, Ruff and owned-path diff checks passed. Production build passed in 14.46 seconds; its existing large-chunk warning remains (`b2a-build-final.log`).
- Browser: 6 passed in 57.7 seconds, exit 0 (`b2a-browser-final2.log`): four actual isolated-agent workflows (public Agent, skill review, run recovery and scheduled context) plus two controlled HTTP receipt UI scenarios (Agent and review). The new Agent pair comprises one real browser/admission/Git-copy/reload/timeline workflow and one controlled UI replay for uncertain admission, cancellation acknowledgement and partial/budget/failed states. The browser agent forces local mock mode; SDK, budget and OS fault proofs belong to the backend tests, not the controlled UI scenarios.
- Both updated subprocess Agent smoke clients passed in forced mock mode, with explicit stdio transport, source session/key and a receipt read back from durable storage (`b2a-smoke-final.log`, `b2a-smoke-default-final.log`).

Logs are in `.verification/` in the reviewed workspace. Prior failed logs remain available: `b2a-backend-debug.log` ended 1127 passed/6 failed before migration assertion and cancellation fixture synchronization. `b2a-browser-final.log` ended 5 passed/1 failed because its programmatic refresh/selection competed with App bootstrap; the corrected real sidebar selection is in the final browser run. The final backend batch was rerun after the saved terminal-receipt projection and execution-copy advisory fixes. Earlier draft evidence is not substituted for this final batch.

Schema038 only adds the source/key mapping. Before upgrade create and verify a consistent SQLite backup. To roll back stop the service, retain the new database/WAL and working-copy evidence, and restore the complete pre-upgrade backup with the matching program version. Source and execution sessions referenced by admitted-agent mappings currently cannot be deleted; archive them instead. Run references remain restricted so deleting history cannot turn the same stable key into a second paid request. A safe tombstone/history-retention flow is deferred. There is no reverse migration or supported JSON replacement of accounting/run history. Removing mappings or budget rows to retry is unsafe and unsupported.
