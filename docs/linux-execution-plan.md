# Linux 产品执行链：分批实施与验收

2026-10-26 迭代决策。本文是后续实现设计，不是已实现能力清单。
已完成的实际环境验证见 [Linux 运行环境](linux-runtime-readiness.md)。
当前仍未完成产品容器执行适配、systemd 长驻、Windows 隧道及断线恢复验收。

## 顺序与依赖

先完成公开直接子 Agent 的持久接单与工作区身份，再把这些运行身份用于容器所有权。
团队入口复用已验收的子任务执行单元，不另建调度循环。
直接子 Agent 及其有序技能绑定已分别在 `623fa16`、`bb5ea49` 验收。
Linux 适配继续复用实际工具依赖、逐 run 身份和撤销检查，不能以容器配置扩大父能力。

Linux 工作分为 L1、L2、L3 三个可分别验收的批次。L1 进程约束通过，不代表 L2
完整 Native 工具链已受限；L2 通过，也不代表 L3 远程产品体验已完成。

## L1：有持久所有权的 Podman 进程适配器

文件、事务状态、公开入口接线和故障窗口矩阵见 [L1 实施规格](linux-process-adapter-design.md)。

接入现有 `execution.py` 的进程创建、输出捕获和 `terminate_tree` 调用关系。
每次执行命令创建一个容器，不通过持久容器中的 `exec` 模拟单次进程所有权。
杀死 Podman CLI 不等于容器或其中的后代已经停止。

创建前先持久保存调用身份：run、工作区、安装实例、策略、镜像、资源、期限，以及
确定性的容器名。随后按以下顺序执行：

1. `create` 创建但不执行；保存 CID，读取并核对实际配置和所有权标签。
2. `start` 并连接输出；限制输出保留量、运行时间及资源。
3. 保存退出或失败证据；取消时等待容器及其后代确实停止。
4. 确认清理结果，再删除本次拥有的容器；保留可用于恢复核对的记录。

不得在证据保存之前使用自动删除，也不得用全局清理或替换同名容器处理冲突。
创建后尚未保存 CID 即崩溃的窗口，通过确定性名称、私有 CID 文件与安装实例标签核对。
启动恢复只操作持久登记且所有权匹配的容器；不能确认的运行保持中断或待核对，
不得自动重放未知写操作。

配置使用已安装版本实际支持的参数并读取结果核验：rootless、非特权用户、只读根文件
系统、关闭网络、去除 capabilities、no-new-privileges、CPU/内存/swap/进程数及临时目录
限制。仅挂载独立任务工作区，不挂载 HOME、凭据、服务数据目录或容器 socket。
固定本地镜像 ID/digest，禁用隐式拉取；镜像、运行时或治理服务缺失即暂停，不退回宿主机。

每个容器的限额之外，还需约束任务家族总并发资源。普通 bind mount 没有磁盘配额，
必须另行落实工作区存储限额，才能宣称无人值守资源约束完整。
容器环境白名单单独定义，不能直接复用包含 HOME/APPDATA/服务数据路径的本机子进程环境。

受限执行目标须独立保存并且不能由内层工作区作用域削弱。目前 `ChildWorkspace.scope`
与 Git 辅助调用会重新构造 `ExecutionPolicy(workspace=...)`；简单往该对象加一个可丢失的
布尔字段不足以保证子任务始终经过容器。

验收使用真实 Linux 合成任务，至少覆盖普通/非零退出、大输出、OOM/进程限制、无网络、
宿主 canary 与秘密不可见、无 socket、命令退出但孙进程仍存活、重复取消、清理期间新后代、
创建/登记/启动各崩溃窗口、运行时消失，以及服务重启后的所有权核对。

## L2：受限 Native 执行配置覆盖完整工具链

第一版仅开放 Native、无网络和已审计工具集合。工具派发与后台启动都执行能力检查，
不依赖提示词要求模型自律。配置在接单、调度和恢复时持久固定；恢复遇到镜像、网络、
资源或工具策略不兼容时阻止继续。

命令及项目校验在容器内执行。宿主文件工具仍由 Python 进程读写，不能因此宣称已获得
容器文件边界；Linux 文件访问须采用可信目录句柄与 no-follow 的安全 I/O，或容器文件
代理，覆盖检查路径到实际打开之间的竞争窗口后，再开放无人值守。

首批受限配置禁用 Hooks、MCP stdio/HTTP、任意 Python provider/plugin 和未经验证的
分析器；已加载的全局连接及自动启动也必须被阻止。只在镜像中已验证的工具才能启用。
索引、预览及图表辅助后台进程按同一规则处理。

仅把 Codex App Server 包进容器不代表其全部工具已受限；在完整覆盖之前不公布该能力。
子 Agent 只有在继承受限目标、工具集合及持久所有权时才能启用。
Git worktree 的 `.git` 可能指向挂载之外；不能为修复它而额外挂载源仓库、HOME 或服务数据。
第一批采用明确的独立副本，或将不支持的 Git 操作禁用并说明原因。

模型 SDK、凭据和数据库留在 Linux 服务端，服务进程及其 OS 账户属于受信边界。
验收必须实际跑通 Native → 容器内修改 → 容器内验证 → 持久回执，并覆盖取消、重启和
所有公开入口，证明没有宿主命令旁路。

## L3：长驻服务、SSH 隧道与主机状态隔离

Linux 使用固定已安装 Python 与预构建 SPA，systemd 用户服务仅监听回环地址。
保留已有 linger 配置；不启用 Podman API socket。服务进程启动不代表就绪，健康检查
还需反映数据库、恢复核对、容器清理和预算治理状态。实测 cgroup 委派与 rootless 兼容，
不直接套用会破坏用户命名空间的服务限制模板。

Windows 本地服务建立 loopback SSH 隧道，校验主机密钥和转发建立结果，关闭 agent
forwarding；通过受认证本地 HTTP/WS 代理访问远端，浏览器不持有远端服务主令牌。
断开隧道或关闭 Windows 不取消远端已经接受的任务。

前端缓存、事件游标、待处理请求和异步响应均按主机、运行实例、会话/run 区分。
切换主机后旧响应不能写入新视图。重连读取持久状态和事件，而非只依赖 WS 内存重放。
原始交付物和数据库保存在执行主机；文件显式上传/下载并校验，不热拷贝正在使用的数据库。
预算仍是每个执行主机数据库的责任记录，不宣称是 Provider 账户跨主机全局费用上限。

实际验收必须覆盖：Windows 关闭后合成任务继续；重连查询同一回执和产物；ACK 丢失
后重试不产生重复副作用；Linux 服务重启展示中断和待核对；错误认证/Origin/Host 被拒绝；
主机切换没有状态串用。合成验证与付费模型任务分别报告。

## 完成定义与回退

每批交付精确源码清单、数据库迁移及兼容说明、实际日志和失败样本。
L1/L2 引入新策略时默认不对旧任务自动补授权，旧计划需重新绑定明确配置。
回退前停止本次拥有的活动执行并保存容器/运行核对证据；旧程序不得继续执行它无法
理解的新受限配置。数据库采用对应备份恢复，不承诺未经验证的逆向迁移。

[生产路线图](production-roadmap.md) 单独验收。
