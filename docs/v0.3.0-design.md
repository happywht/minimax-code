# v0.3.0 Design — "Make it actually useful for coding work"

> Status: **draft for the v0.3.0 plan**. All four tracks read this first.
> Source of truth for: IPC contracts, event shapes, store APIs, file boundaries.

## Goal

Build on v0.2.0 (web + HTTP/WS agent) with 4 substantive features that turn
MiniMax Code from "a chat UI for an agent" into "an actual coding workbench":

1. **thinking_count metadata channel** — close v0.2.0's last known limitation.
2. **Sub-Agent UI** — surface the existing SubAgentRuntime in the chat flow.
3. **Real code-review workflow** — replace the canned `code-review` skill with a
   diff-based review that reads git output.
4. **Git integration** — read-only git status / diff / log exposed as `git.*`
   IPC namespace.

No architecture shifts, no packaging churn. Build on the v0.2.0 web
foundation (Vite + React + agent HTTP/WS).

## 1. thinking_count metadata channel

### Why
v0.2.0 README known-limitation #1: `thinkingCount` is reserved in
`MessageMetadata` but never emitted. The UI shows "思考 N 次" with N=0.
v0.3.0 wires the channel end-to-end.

### Wire format

The `agent.message_chunk` event's `data` field gains a `metadata` object:

```json
{
  "jsonrpc": "2.0",
  "event": "agent.message_chunk",
  "data": {
    "session_id": "ses_xxx",
    "message_id": "msg_xxx",
    "delta": "Hello",
    "done": false,
    "metadata": { "thinking_count": 1, "tokens_in": 12, "tokens_out": 3 }
  }
}
```

Backward-compat: if `metadata` is missing or `thinking_count` is missing, the
UI falls back to 0 (current behavior).

### Agent changes

- `agent/minimax_code/agent/core.py` (or wherever `Context.emit` is called for
  `agent.message_chunk`) — add `metadata` kwarg to the emit.
- `agent/minimax_code/agent/llm.py` — the `MiniMaxClient` mock tracks a `thinking_count`
  counter (start at 0, increment per `chat()` call). Real client reads the API's
  `usage.thinking_tokens` if the field exists, else 0.
- `agent/tests/test_*` — extend existing chat smoke to assert that a
  `message_chunk` event with a non-zero `metadata.thinking_count` arrives
  in mock mode.

### Web changes

- `web/src/types/ipc.ts` — `MessageChunkData` gains optional `metadata?: { thinkingCount: number; tokensIn: number; tokensOut: number }`.
- `web/src/components/MessageItem.tsx` — render the `thinkingCount` from the
  latest chunk's metadata (or fall back to 0).
- `web/src/stores/chat.ts` — accumulate the latest `metadata` per message
  (replace, don't sum — it's a snapshot not a counter).
- `web/src/ipc/__tests__/client-http.test.ts` — extend the WS dispatch
  tests to assert `metadata` flow into the store.

### Tests
- `pnpm --filter @minimax/web test` — all green.
- `cd agent && uv run pytest` — all green.
- `pnpm test:e2e` — all green; new spec `e2e/smoke-thinking-count.spec.ts` opens
  a chat, sends a prompt, asserts the assistant message shows
  "思考 N 次" with N >= 1.

## 2. Sub-Agent UI

### Why
`SubAgentRuntime` exists in the agent (miniMax Code's signature feature
"multi-agent collaboration") but the UI is a thin chip. v0.3.0 makes it a
first-class chat flow: spawn from a message, watch progress live, get the
result backfilled into the main chat.

### IPC additions

- `agent.spawn_subagent` already exists. Extend its `params` to accept:
  - `parent_session_id: string` (so the sub-agent can be linked back to a
    chat turn that triggered it)
  - `context_message_id: string` (the message to anchor the sub-agent's
    run to)
  - `display_name?: string` (override the default agent name in the UI)
- New event: `agent.subagent_progress`
  ```json
  {
    "jsonrpc": "2.0",
    "event": "agent.subagent_progress",
    "data": {
      "run_id": "run_xxx",
      "agent_id": "researcher",
      "parent_session_id": "ses_xxx",
      "context_message_id": "msg_xxx",
      "status": "started" | "thinking" | "tool_call" | "tool_result" | "completed" | "failed",
      "progress": 0.42,
      "summary": "searching the web for..."
    }
  }
  ```

### Web changes

- `web/src/types/ipc.ts` — add `SubAgentProgress` and `SubAgentRun` types.
- `web/src/stores/subAgent.ts` (NEW) — list of `SubAgentRun` per
  session, subscribe to `agent.subagent_progress`, expose a `useSubAgentStore`
  with hooks: `runsForSession(id)`, `spawn(opts)`, `clearCompleted()`.
- `web/src/components/SubAgentPanel.tsx` (NEW) — list of in-flight sub-agents
  with progress bars, status pills, expandable detail. Lives in the
  RightPanel (currently used for Progress / Agent Team).
- `web/src/components/ChatPanel.tsx` — add an "@agent" picker on the
  message input. Picking an agent + Enter spawns a sub-agent; the
  resulting stream backfills into the chat as a "Sub-agent result" card.
- `web/src/components/SubAgentResultCard.tsx` (NEW) — collapsible card
  shown in the chat stream when a sub-agent completes, with the final
  text + a "open run" button that scrolls the SubAgentPanel to the row.

### Tests
- `pnpm --filter @minimax/web test` — store + SubAgentPanel + result card.
- `cd agent && uv run pytest` — extended sub-agent smoke to assert the
  `agent.subagent_progress` events fire with the right shape.
- `pnpm test:e2e` — `e2e/smoke-subagent.spec.ts`: pick an agent from the
  picker, send a prompt, assert the result card appears within 15s.

## 3. Real code-review workflow

### Why
The `code-review` skill is a mock that returns canned text. v0.3.0 turns it
into a real workflow: read git diff, let the LLM (or mock) produce
inline comments anchored to file/line, render them in a side panel.

### IPC additions (new namespace)

- `git.diff(scope: "staged" | "branch" | "working" | <ref>, ref?: string) -> string`
  — returns unified diff text. `scope=branch` defaults to `HEAD~1..HEAD`
  (latest commit on current branch); `scope=working` is unstaged changes;
  `scope=staged` is staged changes; explicit `ref` overrides.
- `git.status() -> { branch: string, clean: bool, ahead: number, behind: number, modified: string[] }`
- `git.log(n?: number) -> [{ sha, author, message, files_changed }]`
- `skill.invoke` for `code-review` (existing) — when invoked with a `diff`
  parameter, the skill reads `params.diff` instead of generating canned text.

### Web changes

- `web/src/types/ipc.ts` — add `GitDiffResult`, `GitStatusResult`, `GitLogEntry`,
  extend `skill.invoke` params to allow `{ diff: string }`.
- `web/src/stores/git.ts` (NEW) — `useGitStore` with `status()`, `diff(scope)`,
  `log(n)`, refetched on session switch.
- `web/src/components/CodeReviewPanel.tsx` (NEW) — file/line list with
  inline comments. Lives in the RightPanel as a new tab.
- `web/src/components/DiffView.tsx` (NEW) — minimal diff viewer (just
  unified-diff text + line numbers + per-line comment marker).
- `web/src/components/SidebarNav.tsx` — add a "Code Review" item that
  opens the panel.

### Tests
- `pnpm --filter @minimax/web test` — git store, diff view, code review
  panel component.
- `cd agent && uv run pytest` — fake-git fixture in the test agent test
  conftest (writes a temp repo, runs `git init`, makes a diff, asserts
  the `git.*` IPC calls return expected strings).
- `pnpm test:e2e` — `e2e/smoke-code-review.spec.ts`: in a real git repo
  (the project itself), request a diff of the working tree, assert the
  response contains at least one `+` line.

### Edge cases
- If the agent cwd is not a git repo, `git.*` calls return an error
  envelope `{code: -32000, message: "not a git repository"}`. The UI
  shows a friendly "Open a git repo to use code review" hint.

## 4. Git integration

### Why
The `git.*` IPC namespace from feature #3 needs handlers. This feature
implements the agent-side `git` handlers (read-only) and a small sidebar
status widget.

### Agent changes

- `agent/minimax_code/ipc/handlers_git.py` (NEW) — handlers for
  `git.status`, `git.diff`, `git.log`. Uses `subprocess.run` to call `git`
  binary; returns structured data.
- `agent/minimax_code/app.py` — `register_app_handlers(server)` also calls
  `register_git_handlers(server)`.
- `agent/tests/test_git_handlers.py` (NEW) — fixture creates a temp git
  repo with a few commits, asserts handlers return expected shape.

### Web changes

- `web/src/components/GitStatusBar.tsx` (NEW) — top-bar widget showing
  current branch + dirty/clean indicator. Click opens a popover with
  the modified file list (calls `useGitStore.status()`).
- `web/src/components/TopBar.tsx` — render `<GitStatusBar />` next to the
  workspace switcher.

### Tests
- `pnpm --filter @minimax/web test` — store + widget component.
- `cd agent && uv run pytest` — new test file.
- `pnpm test:e2e` — extend `smoke-boot.spec.ts` to assert the top bar
  contains the workspace name + a git status indicator.

## Cross-cutting

### Out of scope for v0.3.0
- Mobile pairing (deferred from v0.1.x; explicitly skipped in v0.2.0)
- Multi-user / accounts
- Remote / cloud deployment
- Plugin / extension API
- Real LLM UX polish (rate limits, retry UX, error display) — v0.3.1 candidate

### Dependencies
- All 4 features are independent and can run in parallel.
- `thinking_count` and `sub-agent` both touch the chat stream; the
  dispatch prompts must agree on the `metadata` field shape (defined
  in §1).
- `code-review` and `git` both add IPC; they share the `git.*` namespace
  shape (defined in §3).
- e2e spec file names are reserved: `e2e/smoke-thinking-count.spec.ts`,
  `e2e/smoke-subagent.spec.ts`, `e2e/smoke-code-review.spec.ts`. Don't
  duplicate.

### Tests / e2e
- 4 new e2e specs (one per feature). Each spec must be runnable in < 30s.
- Total e2e: 5 → 9 specs. Should still finish in < 30s total.
- vitest: 158 → ~180 cases. Build still under 0 errors.
- pytest: 14 → ~25 cases. Stdio tests still pass.

### Docs
- README.md — update header (4 new features), remove the
  "thinking_count not implemented" known limitation, add a
  "v0.3.0 usage" section.
- docs/architecture.md — add sub-agent runtime, git IPC, code-review
  flow to the topology diagram.
- docs/ipc-contract.md — document new IPC methods (`agent.spawn_subagent`
  extended params, `git.*`, `code-review` skill params).
- CHANGELOG.md — new `[0.3.0]` section: features + the moved/deleted items.

### Sequencing
1. **Now**: write this design doc → commit → dispatch 4 parallel tracks.
2. **During**: each track lands its feature + colocated tests + commits.
3. **After all 4 done**: 1 docs+verify-as-task track that:
   - Re-runs vitest, pytest, playwright (all green)
   - Updates README/CHANGELOG/architecture/ipc-contract for v0.3.0
   - Writes the v0.3.0 entry in the v0.2.0 e2e specs `Known limitations`
     removal
   - Tags `v0.3.0`

### File boundaries
- Agent: only edit `agent/minimax_code/**` and `agent/tests/**`. Do not
  touch `agent/pyproject.toml` unless adding a dep (which we don't
  need — git subprocess is stdlib, no new deps).
- Web: only edit `web/src/**`, `web/tests/**`, `web/.env.development`,
  `web/.eslintrc.cjs`. Do not touch `web/package.json` deps.
- e2e: only add new spec files; do not modify existing ones unless
  extending (smoke-boot may need a tiny top-bar assertion update).
- Docs: only in the docs+verify-as-task track.
