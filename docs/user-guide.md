# MiniMax Code 用户手册

> 适用版本：v0.17.0 及以上。本手册面向**最终用户**——不需要读代码就能把产品用起来。
> 安装与部署见 [README](../README.md)，生产部署细节见 [deployment.md](./deployment.md)。

## 1. 五分钟上手

1. **启动**：项目根目录执行 `pnpm start`，浏览器打开 <http://127.0.0.1:8765>。
2. **配置密钥**：右上角打开「设置」→「Provider」标签页，添加服务商并粘贴 API 密钥。密钥存入系统钥匙串（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service），不落盘。
3. **开始对话**：左上角「新建任务」，在底部输入框输入问题，`Enter` 发送。

没有 API 密钥也能用：Agent 自动进入模拟模式，界面与工作流完整可用，回复为占位文本。配置密钥后即切换到真实模型。

## 2. 界面总览

```
+--------------------------------------------------------------+
| TopBar：命令面板 Ctrl+K · 预览 · Git 状态 · 通知 · 移动 · 主题 · 设置 |
+---------+--------------------------------------+---------------+
| Sidebar | ChatPanel（对话主区）                 | 检查器面板     |
| 项目分组 | MessageInput（输入框：@提及/附件/语音） | 11 个标签页    |
| 任务列表 | 或 设置页 / 技能库（覆盖层）           | 可折叠         |
+---------+--------------------------------------+---------------+
```

| 区域 | 职责 |
|------|------|
| 顶栏（TopBar） | 命令面板、预览切换、Git 状态、通知中心、明暗主题、设置入口 |
| 侧栏（Sidebar） | 项目分组的任务列表、新建项目/任务、搜索任务历史、Worktree 隔离任务、文本成果、项目附件、连接手机 |
| 对话主区 | 消息流（Markdown/代码高亮/Mermaid 图）、输入框、工具调用卡片 |
| 检查器面板 | 时间线、差异、进度、检查点、Agents、评审等运行时视图（见 §9） |

侧栏的项目分组可折叠（记住状态）；任务按更新时间排序。

## 3. 任务与项目

产品语言里一次对话就是一个「任务」（即会话）。

| 操作 | 做法 |
|------|------|
| 新建任务 | 侧栏「新建任务」按钮，或命令面板 `Ctrl+K` →「新建任务」 |
| 任务归入项目 | 侧栏新建项目后，通过任务选项菜单移动；项目决定侧栏分组 |
| 搜索历史 | 侧栏搜索框，按标题过滤任务历史 |
| 隔离实验 | 「创建隔离的 Worktree 任务」——在独立 Git worktree 中改动，不污染工作区 |
| 重命名 | 双击任务标题（或「任务选项」菜单） |

### 3.1 登记和查看文本成果

当前支持已有 **TXT、MD、CSV** 文件，须为 UTF-8 编码，单文件最大 **2 MiB**。

1. 选择一个项目，并在项目设置中填写明确的本机根目录。
2. 点击侧栏「文本成果」，输入项目相对路径，例如 `reports/result.md`，点击「登记新版本」。
3. 点击列表中的版本查看 SHA-256 和纯文本预览；Markdown 按文字显示，CSV 不执行公式。
4. 源文件修改后再次登记会创建新版本；选择旧版本并点击「下载原始字节」，取得该版本登记时的内容。

登记不会改写源文件，预览和下载使用保存的版本字节。列表当前显示最新 200 条，尚无
翻页入口。「可解析 / 未验证」不代表内容正确、研究完成或交付验收通过。PDF、Office、
图片附件解析及报告/表格质量验证尚未包含在这一入口。

删除项目后，保存的版本文件仍保留在数据目录中，但成果 API 要求项目仍存在，不能
继续通过原项目访问；删除前请下载需要单独保留的版本。完整保存这些版本还需备份
数据库及配套文件目录，见 §14。

### 3.2 上传和查看项目附件原件

1. 选择已有项目，点击侧栏「项目附件」。项目无需设置本机根目录。
2. 选择最大 **10 MiB** 的文件，点击「上传原件」。同名文件每次生成新版本，不覆盖旧原件。
3. 点击版本查看类型候选、解析状态和 SHA-256；TXT/CSV 成功后显示转义的纯文本预览，
   最多 **64 KiB / 2000 行**。选择版本后点击「下载附件原始字节」，取得上传时的全部字节。

TXT/CSV 要求严格 UTF-8，CSV 公式只作文字。空文本、预览截断、解析失败、类型不匹配分别显示；
安装可选 `attachments` 依赖后，DOCX 可预览正文段落与表格，PDF 可按物理页序预览已有文字
（最多200页）；两者仍受上述展示上限限制。PDF不保证版式或表格结构，空页标记表示未提取到文字，
不代表文件没有内容；未尝试 OCR。依赖或资源限制不可用时明确显示解析器不可用。
XLSX 可预览有界的存储单元格值，不重算公式；图片未尝试 OCR。所有状态都保留原件，不能当成已读完。
已解析的 XLSX 在项目附件、办公成果和任务关联成果中可按工作表查看坐标网格。表格使用后端已保存的有界解析记录，最多显示 A1:T100、1500 个已记录单元格及 64 KiB；未显示的格不代表空白，截断时也不能推断其他区域。公式只显示原文及未核验的缓存状态，不计算公式；数字保留存储原值，不推断日期、货币或百分比格式，ISO 日期保留原文。隐藏工作表会标识，不还原合并单元格、图表或布局。原始解析文本与原件下载仍可使用。

当前质量均为「未验证」，不代表研究、报告、表格或交付完成。附件不会自动塞入对话上下文；
在普通聊天中可让 Agent 列出当前项目附件并读取解析预览，截断的预览不能当作全文。
对于 PDF 和 DOCX，Agent 还可按 PDF 物理页或 Word 正文及表格段落继续读取原件；
该功能不做 OCR，也不保证提取 Word 页眉、脚注、修订或文本框。
也可以让 Agent 从上传的 UTF-8 CSV 选择列、转换类型并生成 XLSX；该功能读取完整原件，
支持现有汇总与图表，但有 1 MiB 和 1000 数据行的限制，不修改原文件。
对于简单 XLSX，可指定工作表后选择和转换列。常见日期转为 ISO 文本；百分比和货币保留
底层数值，不保留显示格式。公式、隐藏行列、合并单元格及含义不明确的格式需先在副本中整理。
限制详见 [办公成果](office-delivery.md)。
也可在附件面板或通过 Agent 根据资料生成 DOCX、PDF，或一次生成两种格式；生成文件登记为新附件，
可预览和下载，不覆盖项目原件。支持标题、章节、正文及简单表格，不保证排版、来源事实或业务质量；
可逐条填写来源标题、网址和访问时间，报告会按顺序在文末编号列出；正文引用编号需自行对应，
系统不会自动核验来源。
项目附件及任务关联成果中，可主动选择「查看 PDF 原件」。系统先按服务身份、大小和 SHA-256 校验获取的原始字节，再交给浏览器的内置查看器；此入口限 5 MiB 且要求已有 PDF 文本解析结果，超限或解析失败仍可下载原件。切换会话、项目或服务时关闭预览并释放本地 URL。查看器不是隔离环境，文档中的外链或交互可能访问外部资源；浏览器不支持或显示空白时请下载查看。该视图不代表文档可信、内容正确或版式已验收。
普通 Native 聊天的 Agent 可查询本项目已读取的网页来源，并在后续任务通过来源 ID 将最终网址、标题、访问时间和有界摘录写入报告。来源保存在所属任务日志中，随任务或会话删除而删除；搜索摘要不会自动变成已读取网页。生成报告仍不代表引用关系或事实已核实。
用户也可从侧栏「文本成果 → 研究来源」搜索、查看已保存的项目来源，展开详情查看所属任务、原始摘录和截断标记，复制来源 ID 或手动打开网址。须先选择属于该项目的会话；切换服务或项目后请重新查询。
普通聊天中的生成操作需要写入授权。PDF 需要可用的中文 TrueType 字体；找不到字体时可按
[部署指南](deployment.md) 设置 `MINIMAX_CODE_PDF_FONT`。双格式请求部分失败或响应不明时，
先刷新附件并核对已保存的版本，再只重试缺失的格式。
此面板与输入框原有附件机制分别使用。列表显示最新200条；删除项目前下载需要独立保留的版本。
断开、超时或超限上传不产生可用记录；提交失败请刷新核对，不要把错误响应当作保存成功。
演示模式仅存在页内存，刷新清空。完整持久备份需保存数据库及两个配套 vault，见 §14.1。
安装与准确范围见 [DOCX](attachment-docx.md) 和 [PDF](attachment-pdf.md)；上传文件不会自动安装依赖。

## 4. 对话

普通聊天和只读规划可读取公开 HTTPS 网页，也可使用配置的搜索服务查找资料。
网页结果包含链接、标题、访问时间和有界摘录；搜索需要先设置 SearXNG 端点，
联网操作按权限规则确认。配置和支持范围见 [联网研究](online-research.md)。
输入框提供「专题研究」「资料成稿」「表格处理」模板；点击会将可编辑的任务说明
追加到草稿中，补充目标和要求后再发送，不会自动执行。

### 4.1 输入

| 按键/入口 | 行为 |
|-----------|------|
| `Enter` | 发送消息 |
| `Shift Enter` | 输入框内换行 |
| `@` | 唤起子 Agent 提及选择器 |
| `Tab` | 确认提及选择器当前选中项 |
| 附件 | 输入框工具栏添加附件，随消息发送 |
| 语音 | 输入框麦克风按钮（浏览器语音识别） |

### 4.2 阅读回复

- 回复实时流式渲染，支持 Markdown、表格、代码高亮（代码块右上角一键复制）与 Mermaid 图。
- 助手调用工具时会插入**工具调用卡片**，展示参数与结果；「思考中」状态与轮次摘要在消息头部呈现。
- 消息操作菜单（悬浮）：复制、重试等。

### 4.3 工具授权

Agent 执行敏感工具（写文件、运行命令等）前会弹出**权限请求对话框**，展示工具名与参数：

- **允许** / **拒绝**：对本次调用放行或拒绝（`Enter` = 允许，`Esc` = 拒绝）；
- **总是允许**开关：批量放行同类请求，规则可在「设置 → 权限」管理/删除。

权限弹窗若涉及文件补丁，会同时预览改动内容（Patch 预览），确认后再落盘。

## 5. 模型与密钥

设置页分三个相关标签，分工如下：

| 标签 | 管什么 |
|------|--------|
| Provider | 服务商接入：地址、模型映射、密钥（多 Provider 并存） |
| 模型 | 当前会话用哪个模型；每个 Provider 的模型注册表（增删自定义模型 ID、上下文窗口） |
| API 密钥 | 旧版内置 MiniMax 密钥（兼容入口）；显示密钥状态：已存钥匙串 / 环境变量 / 未配置（模拟模式） |

切换模型：输入框上方的模型选择器，或「设置 → 模型 → 使用」。上下文窗口以 `XXk 上下文` 标注，支持工具调用的模型带「支持工具」标记。

`Ctrl+K` 打开命令面板，可直达：新建任务、预览面板、技能库、全部设置标签、任意历史任务（支持模糊搜索）。

## 7. 技能库

命令面板 `Ctrl+K` →「技能库」打开技能面板。技能 = 预封装的任务流程（SKILL.md 定义，可含工具绑定）。浏览已安装技能、查看说明、一键调用。技能规格见 [skills.md](./skills.md)。

## 8. 多 Agent 协作

### 8.1 子 Agent

对话中输入 `@` 提及子 Agent，把一段工作委托出去。子 Agent 的进度实时出现在：

- 检查器「子 Agents」标签：运行状态、产出；
- 「Agents」标签：Agent 定义管理（也可在「设置 → 子 Agent」配置）。

### 8.2 团队（Agent Teams）

「设置 → 团队」把多个 Agent 编成团队，分工协作跑复杂任务。团队运行时看检查器「团队运行」标签：每个成员的轮次、接力与汇总。「时间线」标签呈现整次运行的时序视图。

## 9. 检查器面板（右侧）

已有项目可通过侧栏项目菜单的「项目验证设置」编辑根目录与验证命令。Native 可写任务正常完成后，会在其工作区执行接单时保存的命令；Codex 可写任务正常完成后先逐次请求主机执行授权，获准且会话、项目和工作区仍匹配时执行。右侧时间线对应任务的「查看验证命令与输出」展示已记录的命令、退出码、超时、错误和截断后的输出。拒绝或超时授权、规划模式、未配置命令及未正常完成的任务不会得到验证通过结论。命令执行的是宿主 shell，可访问主机文件和网络，不受 Codex 工作区沙箱保护，须由用户自行信任。更新设置只影响之后接单的任务，已绑定独立工作区的会话仍使用自己的目录。

新 Native 任务的报告和表格生成工具返回已确认保存的成果后，时间线可直接打开关联附件的有界纯文本预览或下载原件。预览与下载会复核当前会话、项目、服务身份及附件校验值；幂等请求可能返回以前保存的成果，关联只表明本任务的工具返回了它。业务内容和版式仍未验证。旧任务、手工生成的成果、未确认保存的结果或未成功记录关联的附件不会自动归入任务，可在项目附件或办公成果中查找。

时间线中可用「查看工作区当前差异」读取该任务绑定目录的 Git 状态：分别查看已暂存、未暂存的已跟踪文件差异和未跟踪文件名。这里展示查询时的共享工作区，可能包含用户或其他任务的修改，也可能在任务结束后继续变化；它不是任务独有的变更记录，不包括已提交的变更或未跟踪文件的内容。各部分分别读取，工作区正在变化时结果不保证是同一时刻的快照。旧任务缺少项目或工作区绑定、绑定发生变化，或者目录不是 Git 仓库时，不能使用此视图。

发送前可勾选「采集任务前后文件变化」；默认关闭。运行实际开始前与结束后分别读取绑定目录中 Git 已跟踪及未忽略的未跟踪普通文件，时间线的「查看任务前后文件变化」列出新增、修改和删除的路径，不保存文件内容。每次最多 1000 个文件、16 MiB 内容，Git 列举和文件读取各限 2 秒；超限、不可读取、链接或绑定变化时结果不可用，任务仍继续运行。Git 忽略文件、`.git` 和 `.minimax` 不纳入；独立工作区只检查自身。采样不是原子快照，也可能包含用户和其他任务同期修改，不能归因给 Agent；服务重启无法补采之前的基线，旧任务不会自动获得此记录。

| 标签 | 内容 |
|------|------|
| 时间线 | 当前任务的事件时序（消息/工具/里程碑） |
| 差异 | 工作区文件改动（配合 Git 状态） |
| 进度 | 任务步骤清单与完成度 |
| 检查点 | 快照列表——从某个检查点恢复上下文 |
| Agents | Agent 定义与管理 |
| 子 Agents | 本次任务的子 Agent 进度与结果 |
| 评审 | Code Review 工作流（见 §11） |
| 团队运行 | Agent 团队执行明细 |
| 终端 | 命令执行输出 |
| Runner | 运行器状态 |
| 代码库 | 代码库索引/检索视图 |

连接恢复后，当前会话会刷新运行时间线；任务仍在运行时，聊天会补入该任务最近已保存且本页缺失的工具结果，不替换正在流式显示的文本或本地输入。任务结束后再恢复已保存的聊天记录。工具结果只在服务端写入后可恢复；读取范围为最近 500 条消息及时间线最近 20 次运行，聊天已达到显示上限时不会为补取结果丢弃当前内容。连接或读取失败时保留现有视图，可在重新连接后重试。

同一 Agent 服务进程仍在等待时，重连会重新显示当前会话尚未回答的 Native 提问及尚未决定的 Native 或 Codex 工具权限审批。恢复只显示审批，不自动授权；已经回答、决定、取消或到期的请求不能再次提交。计时仅为提示，服务端在收到回答或决定时再次核对是否有效。服务进程或 Codex 进程退出会结束相应内存等待，不能借此继续旧请求。

服务进程仍运行时，当前会话的 Native 和 Codex 流式文字会在重连后从内存快照补齐；增量按消息段序号去重，缺口会触发再次读取。此快照最多 2 MiB UTF-8、2 万个增量或 256 个消息段，超限后仍显示后续实时文字，但无法补齐之后漏收的内容，界面会提示任务结束后查看已保存记录。它不是持久日志：服务重启后未保存的 Native 中途输出无法由该快照恢复；任务最终保存的记录仍为准。

输入区的「排队一个新任务」接收纯文本，作为当前会话的独立任务排在已有任务之后；没有前序任务时立即运行，不会插入正在执行的轮次。提交后以时间线的任务状态为准，尚未开始的已接收内容可以展开查看（最多显示 8000 字）。同一会话有上限，停止会话也会取消排队任务。Codex 若前序任务结果不确定，后续任务会停止并要求先核对；这里不提供 Codex steer。

浏览器发送排队任务前会保存本地重试凭据；响应不确定时保留正文，检查时间线后可重试同一请求而不重复接单。移除本地待确认记录不会取消服务端已接收的任务。浏览器存储不可用时无法提交此入口；重连可从服务端恢复已接收的任务。服务重启后的未完成任务依照现有中断和人工恢复规则处理，不会自动续跑。

Native 正在运行的任务可在时间线选择「向此 Native 任务补充」。补充会等待当前工具批次完成，在下一模型轮次边界加入上下文，不会中断工具；如果任务先结束、取消或进程重启，补充可能未被使用。时间线显示已接收、已加入上下文或未确认生效，加入上下文不保证模型已经接收或遵循。断线时可用同一凭据重试并查看状态；此功能与排队新任务不同，Codex 不支持中途补充。

Native 任务的大型工具输出可在时间线选择“查看已捕获输出”分页查看，Agent 也可按引用分页读取。保存内容仅是工具实际捕获的数据；命令的 stdout 与 stderr 各最多捕获 5 MiB，超出部分无法恢复。单条记录最多 12 MiB、单次运行和全库各最多 32 MiB，并为数据库备份保留空间；达到限制或存储失败时仅保留截断预览。输出可能包含敏感信息，保存在本地数据库并随所属运行删除；没有持久运行绑定的旧输出不由此功能恢复。

聊天中的“检查当前会话目录”按会话独立目录、项目根目录、服务进程默认目录的优先级检查目录是否可解析，并标明来源。未知或超时不等于目录故障；UNC 网络路径和无法确认执行边界的会话不会被此检查验证，映射驱动器是否远程也未判断。该检查不执行命令，不验证写权限、模型连接或远程环境，也不是操作系统沙盒。

时间线的“工具输出存储与清理”显示全库及当前会话的逻辑用量。可在当前会话逐条清理已终结任务的捕获输出，清理后不能再读取，但任务、摘要和原文件保留；系统不会自动清理。SQLite 文件不一定立即缩小，旧备份及介质可能仍包含原始内容，清理不是安全擦除。

## 10. 自动化

| 功能 | 入口 | 说明 |
|------|------|------|
| 定时任务 | 设置 → 定时任务 | cron 表达式驱动，到点自动开任务执行提示词 |
| 工作流 | 设置 → 工作流 | 串联多步骤的固定流程 |
| Webhook | 设置 → Webhook | 事件发生时回调外部 URL |

定时任务行显示当前发生的持久运行状态；出现“等待授权”时，可打开对应会话处理。历史记录会随运行事件和重连刷新，断线时标记状态待刷新。任务使用本地 Native 调度，服务停止期间不会执行；等待授权并不等于已获得授权。

展开定时任务历史后，可对已接单的发生记录选择“查看本次运行结果与成果”。详情核对发生记录和运行的会话、项目、目录及 Native 绑定，显示读取时状态和已保存的文本回执；关联的 DOCX、PDF、XLSX 可查看已有有界预览并下载原件。历史缺少绑定、尚未接单、没有回执或没有关联成果时会分别提示；旧的未关联文件不会归到该任务。附件内容仍需业务核对，详情不是远程执行或无人值守运行的证明。

## 11. Git 集成、Code Review 与 Patch Studio

## 14. 数据：导出、导入、备份

「设置 → 数据」三个动作，语义不同：

| 动作 | 格式 | 何时用 |
|------|------|--------|
| 导出数据 | 单个 JSON 文档（含 schema 版本，覆盖全部业务表） | 跨版本迁移、换机器 |
| 从 JSON 导入 | 替换式：文件中每张表在单事务内覆盖当前内容（要么全成，要么全不做） | 恢复导出文件 |
| 立即备份 | SQLite 文件级热快照（带 UTC 时间戳，Agent 不停机） | 同版本灾备 |

导入前会弹出确认（显示行数与 schema 版本）。**大规模导入前请至少保留一份备份**；旧版本会拒绝导入新 schema 的文件，而不是损坏自身。

文本成果的 JSON 导出只包含登记元数据，不包含文件内容；「立即备份」也只生成数据库
快照。保留或恢复文本成果时，须同时保存匹配的数据库与 Agent 数据目录中的
`text-artifact-vault` 文件夹。只导入 JSON 或只恢复 SQLite 文件不会补回缺失的原始
版本字节。

项目附件原件同样单独保存在 `attachment-vault`，JSON/SQLite-only 恢复也不能补回它们。

### 14.1 离线保存数据库、文本成果及附件原件

停止使用源数据目录的 Agent 后，可在已安装依赖的 `agent/` 目录执行：

```bash
uv run python -m minimax_code.bundle create --data-dir /absolute/stopped-data --output /absolute/backups/data-vault.zip
uv run python -m minimax_code.bundle verify --bundle /absolute/backups/data-vault.zip
uv run python -m minimax_code.bundle restore --bundle /absolute/backups/data-vault.zip --new-data-dir /absolute/fresh-data
```

将示例路径换成实际路径（Windows 也支持，空格须加引号）。父目录须已存在，输出包
位于源数据目录外，恢复目录必须全新且不存在。正在占用目录的服务、链接/损坏/超限
文件或不支持的格式会使操作失败；不会覆盖已有目标。该包保存一致 SQLite 快照和
全部已登记历史文本版本及附件原件，孤儿/待发布文件只计数、不收取。
当前新包为v3/Schema043；仍能校验/恢复旧v1/Schema041、v2/Schema042，不自动迁移，旧工具拒绝v3。
任一已登记原件缺失或损坏都会失败，不会默默跳过无法解析的附件。

这是 **data-only 副本，不能直接作为可运行实例启动**。数据库中的原主机路径、凭据、
定时任务及执行/安装身份保持原值，后续运营前须另行显式安全重新绑定。命令不启动
服务、调度、插件或模型。项目树、`.minimax`、未登记外部附件/配置/技能/插件文件、SSH、
钥匙串及容器/镜像不包含在内；包中的数据库本身仍可能含敏感字段。Windows 尚未验证
目录项断电持久性。这不替代完整应用备份或安装恢复演练；范围和限制见
[离线数据包说明](data-vault-bundle.md)。

# 子任务工作区审阅与收集

打开当前会话的子 Agent 面板后，最近 100 个有持久父任务绑定的直接子任务会在刷新或重连时恢复。服务无法确认仍在运行的未终结记录会显示“状态待核对”，包括可能由父任务同步等待的子任务；旧的无绑定记录及更深层子任务不在此列表中。

在子 Agent 面板展开已完成的内部子任务，选择“查看子任务工作区结果”，可查看当前父目录与子任务结果的文件差异；这不能证明同期变化由 Agent 造成。确认后选择“收集已审阅的无冲突变化”。存在父目录冲突或子任务删除时必须手动处理；收集期间出错可能部分写入，应重新查看和核对。差异过大、非 UTF-8 或超出显示预算时需手动查看原文件。子任务工作区及备份保留。仅支持可核实持久父运行绑定的直接子任务；旧记录、嵌套或受限执行子任务不能从此入口收集。普通独立工作目录不是操作系统沙盒。
