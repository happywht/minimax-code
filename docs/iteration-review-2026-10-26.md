## 第二优先级：补齐 RunService 的公开执行入口

这是预算稳定后的首个实现批次。当前 fail-closed 是临时保护，后续应恢复功能，
让技能、审查、直接子 Agent 和团队从统一持久入口运行。

按可验证的小批次推进：

1. **技能与代码审查**：`skill.invoke` 创建持久 run，保存请求键、项目、模型、
   权限与预算；流式输出仍兼容现有调用方，UI 能打开真实运行记录。
2. **直接子 Agent 与团队**：`agent.invoke`、`agent.spawn_subagent`、`team.spawn`
   复用相同接单契约；根任务创建预算家族，递归后代继承；取消等待实际清理完成。
3. **其他付费旁路**：单独定义行内补全的短请求预算及生命周期。
   旧 workflow 的失效 run-skill 分支先修好真实调用契约，再开放；不靠旁路恢复付费。

每一批的验收标准相同：真实 handler + 受控 SDK + SQLite 跑通，重复请求只执行一次；
断线不丢回执，重启标记中断且不自动重放未知写操作；子任务额度与结果可追溯；
运行中不得静默切换已固定的模型、目录或扩大权限；权限撤销应继续收紧执行。

同时补齐剩余 M1 子进程入口审计，例如自动检查点的 Git 探测。
规划模式跳过自动检查点，避免写入 Git 对象或复制文件；其他模式的探测复用已有
进程策略、环境过滤、超时与清理，不为任意工具命令增加只读策略的绕过入口。

## 第三优先级：把 Linux 容器准备变成产品运行能力

先做执行适配器，再做长驻服务和 Windows 连接流程。

- 执行适配器消费固定运行上下文，限定挂载、用户、网络及资源；运行时缺失即暂停，
  不回退宿主机 shell。容器 ID 和工作区归属持久保存。
- 使用无真实凭据的任务验证取消、超时、服务崩溃和后代进程回收；真实项目和凭据按需接入。
- Linux 服务仅监听回环，Windows 本地服务通过 SSH 隧道代理；SSH 断开不拥有任务生命周期。
- 主机切换清理前端状态，数据和原始产物留在执行主机，文件显式传输并校验。

实机通过门槛是：Windows 关闭后任务继续，重连后能读取同一个 run 的完整状态及产物；
重复提交无重复副作用；服务重启能解释中断状态。当前容器约束验证不能替代这些门槛。
运行环境证据见 [Linux 准备验证](linux-runtime-readiness.md)。
