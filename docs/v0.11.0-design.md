# v0.11.0 架构设计文档 — Agent 能力增强与编码工作流闭环

> 版本：v0.11.0（设计稿）  
> 目标发布周期：6 周  
> 设计日期：2026-07-27  
> 状态：Draft → 待 v0.10.3 完成后进入开发

---

## 1. 背景与目标

v0.10.x 解决了「项目/会话」的组织分层问题，并把空状态、侧边栏交互等基础体验打磨到可用状态。v0.11.0 的目标是让 MiniMax Code 从「能聊天」进化为「能独立完成复杂编码任务」：

- **工具生态**：通过 MCP 连接外部工具（浏览器、数据库、设计稿、文档等）。
- **代码理解**：基于本地代码库的索引与检索，让 Agent 拥有项目级上下文。
- **长期记忆**：跨会话保留关键决策、失败教训、项目约定。
- **协作编排**：多 Agent / Team 可视化编排与结果合并。
- **Patch 工作流**：把 LLM 生成的代码变更变成可审查、可回滚、可批量应用的 Patch。

---

## 2. 设计原则

1. **渐进增强**：所有新能力默认关闭或 opt-in，不影响现有 chat/项目体系。
2. **前后端契约先行**：任何新 IPC / 事件 / 数据模型先在文档中定义，再实现。
3. **可测试**：新增 handler、DAO、组件必须配套单元/集成测试。
4. **本地化优先**：索引、记忆、Patch 优先在本地完成，不强制依赖云端。

## 4. 核心能力模块

### 4.1 MCP / 工具生态

**目标**：让 Agent 能调用外部工具服务器，而不只是把工具硬编码在 Python 里。

#### 后端
- 新增 `minimax_code/mcp/` 包：
  - `client.py`：MCP client，通过 stdio/sse 连接外部工具服务器。
  - `registry.py`：工具发现、注册、生命周期管理。
  - `adapter.py`：把 MCP tool schema 转成项目内部的 ToolDefinition。
- 新增 IPC 命名空间 `mcp.*`：
  - `mcp.list_servers`：列出已配置的 MCP 服务器。
  - `mcp.add_server` / `mcp.remove_server`：增删配置。
  - `mcp.list_tools`：列出某个服务器暴露的工具。
  - `mcp.invoke_tool`：调用 MCP 工具（复用现有 `agent.send_message` 的工具调用通道）。
- 配置持久化：在 `settings` 表或新增 `mcp_servers` 表中保存服务器配置。

#### 前端
- Settings 新增「MCP Servers」tab：
  - 表单：name、transport（stdio/sse）、command/url、env。
  - 工具列表展示与启用/禁用开关。
- Tool 调用结果渲染：区分 built-in / mcp tool，显示来源服务器。

#### 数据模型
```sql
CREATE TABLE mcp_servers (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    transport TEXT NOT NULL,  -- 'stdio' | 'sse'
    command TEXT,
    url TEXT,
    env TEXT,                 -- JSON object
    enabled INTEGER DEFAULT 1,
    created_at TEXT,
    updated_at TEXT
);
```

### 4.2 代码索引与检索（Codebase RAG）

**目标**：让 Agent 能基于项目代码库回答「这个模块是做什么的」「哪里用了这个函数」。

#### 后端
- 新增 `minimax_code/codebase/` 包：
  - `indexer.py`：基于 `tree-sitter` 解析代码结构，提取 symbols、definitions、calls。
  - `embedder.py`：把代码块编码为向量（默认使用本地轻量模型，可选云端）。
  - `store.py`：向量存储 + 倒排索引，可选 SQLite FTS 或 faiss/annoy。
  - `retriever.py`：混合检索（关键词 + 向量 + 图关系）。
- 新增 IPC 命名空间 `codebase.*`：
  - `codebase.status`：索引状态（未开始/进行中/完成/失败）。
  - `codebase.build_index`：触发全量或增量索引。
  - `codebase.search`：搜索代码（支持 query、limit、file_pattern）。
  - `codebase.summarize`：对某个文件/目录生成摘要。
- 索引任务放在后台线程/进程，避免阻塞主事件循环。

#### 前端
- 聊天输入增加 `@repo` / `#file` 提及：
  - `@repo explain auth flow`
  - `#file src/auth.ts summarize`
- 新增「代码库」侧边栏面板：
  - 索引进度条。
  - 热门文件、最近变更、搜索框。
- Assistant 消息中引用代码块时显示「来源文件」标签。

#### 数据模型
```sql
CREATE TABLE codebase_chunks (
    id TEXT PRIMARY KEY,
    file_path TEXT NOT NULL,
    start_line INTEGER,
    end_line INTEGER,
    content TEXT NOT NULL,
    embedding BLOB,           -- optional, if vector store in sqlite
    metadata TEXT,            -- JSON: language, symbols, etc.
    created_at TEXT,
    updated_at TEXT
);

CREATE INDEX idx_codebase_chunks_file ON codebase_chunks(file_path);
CREATE VIRTUAL TABLE codebase_chunks_fts USING fts5(file_path, content);
```

### 4.3 长期记忆（Memory）

**目标**：跨会话保留项目约定、用户偏好、失败教训，减少重复沟通。

#### 后端
- 新增 `minimax_code/memory/` 包：
  - `extractor.py`：从对话历史中抽取 key facts（使用轻量 prompt + 结构化输出）。
  - `store.py`：记忆存储与检索。
  - `injector.py`：在新会话启动时把相关记忆注入 system prompt。
- 新增 IPC 命名空间 `memory.*`：
  - `memory.list`：列出记忆（支持 project_id 过滤）。
  - `memory.add`：手动添加记忆。
  - `memory.delete`：删除记忆。
  - `memory.search`：按内容搜索记忆。
- 触发时机：
  - 会话归档/结束时自动提取。
  - 用户显式「记住这一点」。

#### 前端
- 新增「记忆」tab / 面板：
  - 记忆卡片列表（内容、来源会话、时间）。
  - 手动添加/编辑/删除。
- 聊天中支持 `/remember <内容>` 快捷指令。

#### 数据模型
```sql
CREATE TABLE memories (
    id TEXT PRIMARY KEY,
    project_id TEXT,
    session_id TEXT,
    content TEXT NOT NULL,
    category TEXT,            -- 'preference' | 'decision' | 'lesson' | 'fact'
    confidence REAL,          -- 0..1
    created_at TEXT,
    updated_at TEXT,
    FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE,
    FOREIGN KEY (session_id) REFERENCES sessions(id) ON DELETE SET NULL
);
```

### 4.4 Agent 编排（Agent Studio）

**目标**：可视化编排多个 Agent / Team 的执行顺序与结果合并方式。

#### 后端
- 扩展 `agent_teams` 表：
  - 增加 `orchestration_mode`：
    - `sequential`：顺序执行。
    - `parallel`：并行执行。
    - `vote`：多 Agent 投票合并。
    - `review`：先生成后由 review agent 审查。
- 新增 `team.spawn` 返回 `run_id`，通过 `agent.subagent_progress` 事件流输出每个子 Agent 的状态。
- 新增 `team.run.get` 查询运行结果和冲突列表。

#### 前端
- Agent Studio 页面：
  - 画布式/列表式编排节点（Agent、Team、Decision Gate）。
  - 配置每个节点的输入模板、输出变量、重试次数。
- TeamRunPanel 增强：
  - 显示执行 DAG。
  - 冲突文件高亮与合并建议。

---

### 4.5 Patch 工作流闭环

**目标**：让 LLM 生成的代码 diff 可以被审查、单块应用、回滚。

#### 后端
- 复用并增强现有 `patch.*` handler：
  - `patch.preview`：返回结构化 diff + 文件列表。
  - `patch.apply_hunk` / `patch.revert_hunk`：已存在，需增强冲突检测。
  - 新增 `patch.apply_file`：应用单个文件全部 hunk。
  - 新增 `patch.apply_all`：应用当前 scope 全部变更。
  - 新增 `patch.save_snapshot`：应用前自动 git stash / 备份。
- 与 Git 集成：应用前检查工作区是否干净，必要时自动 stash。

#### 前端
- Patch Studio 面板：
  - 文件树 + hunk 列表。
  - 每块变更支持「应用 / 跳过 / 回滚」。
  - 全局操作：应用全部、放弃全部、生成 commit message。
- 聊天消息中 assistant 的代码变更以「Patch Card」形式展示，可直接进入 Patch Studio。

## 7. 关键技术选型

| 能力 | 候选方案 | 建议 |
|------|----------|------|
| 代码解析 | `tree-sitter` Python bindings | ✅ 推荐，速度快、语言多 |
| 向量存储 | `sqlite-vec` / `faiss-cpu` / `annoy` | 先 `sqlite-vec` 保持零依赖，规模大了再换 |
| MCP transport | stdio + SSE | 先支持 stdio，SSE 后续 |
| 记忆提取 | 轻量 prompt + Pydantic 结构化输出 | 默认用现有 MiniMax 模型，失败可降级 |
| Patch 应用 | `git apply --3way` + 自定义 fallback | 优先 git，失败时按行级合并 |

---

## 8. 风险与回退策略

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 代码索引占用大量磁盘/内存 | 性能 | 默认排除 `node_modules`、`.git`、二进制；支持排除模式；索引任务可取消 |
| MCP 工具调用失败/超时 | 体验 | 每个 MCP server 独立进程，超时后隔离；失败时标记不可用 |
| 记忆提取质量差 | 误导模型 | 默认低 confidence 不注入；用户可手动管理；提供开关 |
| Patch 应用冲突 | 代码损坏 | 应用前自动 stash / 备份；冲突时拒绝应用并提示 |
| 新增 IPC 破坏旧前端 | 兼容性 | v0.11.0 新能力用新命名空间，不影响已有 `session.*` / `agent.*` |

## 9. 里程碑拆分

### Milestone 1：基础设施（第 1–2 周）
- MCP client 基础框架 + `mcp.list_servers` / `mcp.add_server`。
- Patch 工作流增强：`patch.apply_file` / `patch.apply_all` / `save_snapshot`。
- 数据库迁移文件准备。

### Milestone 2：代码理解（第 3–4 周）
- `codebase.build_index` 与 `codebase.search`。
- 前端 `@repo` / `#file` 提及与结果渲染。
- 代码库索引进度面板。

### Milestone 3：记忆与编排（第 5–6 周）
- `memory.*` 后端 + 前端管理面板。
- Agent Studio 编排画布与 `team.spawn` 事件流。
- 全量测试与文档更新。
