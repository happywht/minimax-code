# 生成并登记纯数据 XLSX

## 多条件任选筛选（未验证）

聊天导入 CSV 或 XLSX 时，`generate_xlsx_from_csv` 和 `generate_xlsx_from_xlsx` 的 `filter_mode` 可设为 `any`，保留满足至少一条筛选条件的行，例如筛选“部门是设计部，或金额大于 10000”。不传时默认为 `all`，保留满足全部条件的行；`any` 必须至少提供一条条件。各条件仍使用原有的类型、空白与文本匹配规则，完整输入先经过类型校验；筛选发生在计算之后、去重和分组之前。输出顺序和来源原件不变，生成的 XLSX 是新成果。

任选模式及条件写入成果处理说明并参与请求键冲突判定；更改筛选方式或条件须使用新请求键。旧成果及默认 `all` 的回执格式不变，旧版程序可能无法读取包含任选模式的回执或备份。结果及业务口径仍需人工核对。本改动未运行测试、构建或实际操作验证。

成果侧栏 →「办公成果」提供真实后端的手动入口。普通聊天 Agent 也可根据用户提供或已读取的资料调用 `generate_table_xlsx`，由服务端绑定当前会话项目；生成前遵守写入权限（默认请求确认），规划模式不允许写入。Agent 返回成果 ID，可在办公成果列表中按 ID 找到并下载。选择有明确绝对根目录的项目，填写显示文件名和结构化 JSON，点击「生成并登记 XLSX」。操作只新建私有 vault 文件，不读取、修改或覆盖项目原文件；普通附件上传、模型回复和已有文本成果不会自动成为办公成果。

本片仅支持一个可见工作表的 text / number / boolean / null。最多 20 列、1000 数据行，含表头最多 5000 格；规范输入 1 MiB、输出 2 MiB。列名大小写折叠后唯一，每行宽度匹配。text 最长 4096 字符，空串规范化为空白；长编号与前导零请使用 text。数字最多 15 个有效位，绝对值不超过 999999999999999，非零绝对值至少 1e-12；拒绝负零、NaN、Infinity 和把布尔值当数字。

也可在「从 CSV 创建表格输入」中粘贴文本或选择本地 UTF-8 CSV 文件（最多 1 MiB）。文件只在浏览器本页读取，不会被上传或登记为项目附件；源文件不修改。空 CSV 草稿会直接载入并展示列；已有草稿时须明确点击替换，读取失败、取消或切换项目不会覆盖草稿。分页表格支持编辑数据单元格、重命名及左右调整列、新增或删除行列、移除所有单元格均为空字符串的行。可主动去除指定列数据单元格的首尾空白；该操作可能改变文本，不会自动执行。列类型随列移动或删除，新列默认为文本。行号以当前表格为准，含表头；空格不是空字符串。可恢复到本次读取时的表格，恢复同时把列类型重置为文本。表格有编辑时 CSV 原稿暂为只读，明确恢复或替换后才能重新编辑；表格编辑只保留在当前页面。为每列选择文本、数字或布尔，明确点击转换替换 JSON 编辑器内容，失败则保留 JSON 并提示错误；生成时提交转换后的表格数据。首行为表头，支持引号转义、引号中的逗号和换行。默认按文本处理以保留前导零和公式样文本；数字只接受安全精度的十进制表示（含指数），布尔只接受 true/false，空字符串转空白。编辑和生成仍受 1–20 列、1000 数据行、含表头 5000 格、输入 1 MiB 等限制，服务端执行最终校验。请在生成前核对转换后的输入；这不是完整表格编辑、业务核验或公式工作流。

表格编辑器可选择一列或多列作为去重键，先显示预计删除和保留的行数，再由用户点击删除。仅当所有选中列的原始字符串完全相同时判为重复，空字符串也参与匹配；不自动去空白、不忽略大小写，保留当前顺序的第一行。更改列结构或列名后须重新选择键。去重只改变页面草稿，恢复读取时的表格可撤销全部草稿编辑，源 CSV 和项目附件不变。转换为表格输入后仍须生成 XLSX 才会产生新的交付物。

表格草稿可显式按单列升序或降序排序。文本按 UTF-16 码元顺序比较并区分大小写；数字使用转换为表格输入时的安全精度规则，任何非空值无效时拒绝排序并保留草稿。空字符串在两种方向下均排在最后，相等值保持原顺序。排序可通过表格编辑器撤销，不修改源文件或项目附件；需重新转换表格输入后才会影响后续生成。

示例输入：

```json
{
  "sheet_name": "清单",
  "columns": [{"name": "编号", "kind": "text"}, {"name": "数量", "kind": "number"}],
  "rows": [["00012345678901234567", 12], ["=原样文本", 3], [null, 0]]
}
```

文件名只是 `.xlsx` 显示和下载名称，不是主机路径。表名、列名和值拒绝非法 XML 字符。以 `=`、`+`、`-`、`@` 开头的文字、错误标记和 URL 均强制保存为字符串，不创建公式或超链接。文件不包含宏、外部关系或嵌入对象；不访问外网，不执行模型或办公软件，不产生费用。

可选既有 Run ID 只作历史来源引用：当前服务同项目、会话显式绝对 workspace 与项目根一致的普通 native host 非 plan run；含 admitted/internal 执行元数据、其他引擎或隔离配置的会话不支持。完整会话历史按批检查，每条 metadata 最多 64 KiB；超限、嵌套过深或非严格 JSON 拒绝，不抽样放行。生成前和提交时复核绑定，不借用 run 的工具权限，不恢复或完成 run，也不证明文件由该 run 生成。可以不关联 run。

## 保存、验证和失败语义

新建文件使用已锁定的 openpyxl 3.1.5，在固定受限子进程中生成。独立验证器检查保存后的全部 ZIP/XML 和单元格坐标、类型、值，完整比较规范输入，拒绝公式、外部关系、宏、额外部件、遗漏或额外单元格。验证不依赖预览窗口。报告固定 `scope=xlsx_plain_cells_v1`、`structure_status=passed`、`business_quality=unverified`、`render_status=not_attempted`，记录输入/文件 SHA-256、计数、库与验证器版本。

这代表纯数据结构和值核对通过。没有 Excel/PDF 渲染、版式/字体/分页验收、OCR、公式重算或业务正确性验收。报告不是数字签名；有人同时篡改文件和报告时，报告本身不提供真实性保证。

Linux/Windows 原生资源门沿用附件解析器：512 MiB 内存、10 CPU 秒，Windows Job Object 限一个进程并随父关闭，Linux 资源限制和父死亡信号；不支持的平台或资源门失败时拒绝生成。固定 Python worker 使用 `-I -B -S`，只接收结构化 JSON，环境仅保留必要 Windows 系统变量，不接收 API key、数据库/vault 路径、shell 或用户命令。生成 wall 15 秒、排队 5 秒、服务总预算 40 秒，stdout 3 MiB、stderr 16 KiB；这不是可执行不可信程序的通用 OS 沙盒。

独立预览进程复用已有 XLSX 严格解析，必须成功后才登记。预览为转义纯文本，A1:T100 / 1500 格 / 64 KiB 等现有上限可能截断；它不还原 Excel 排版。下载复用认证附件字节端点，服务核对不可变快照大小/hash，前端再核对实际字节大小/hash与项目/主机/服务身份。

私有文件先 fsync 并无覆盖原子发布，attachment 元数据与 office receipt 在一个事务内提交。只有提交且回读成功才返回结果；失败不写“已交付”状态。同项目与 request_key 相同且规范请求及项目 id/root_path/created_at 绑定相同则重放同一记录，内容或项目根变更时拒绝；点击“生成同名新版本”使用新 key，保留原文件。修改表格、名称或 run 会切换 key。

取消/超时先终止并回收实际 worker，文件线程与事务必须收束后释放槽。页面切换只停止本页等待，不保证服务器取消；提交边界丢失响应时刷新或同 key 重试可找回已提交记录。文件已发布但数据库失败时，可能留下一份完整私有 orphan；没有登记行或可下载成果，不会自动补录、重扫或删除其他文件。不可用/损坏快照拒绝预览和下载，没有源文件 fallback。

## 独立复验

生成成功后，点击“下载此成果的输入 JSON”“下载 XLSX 原始字节”“下载校验报告”，保留三者。输入快照仅在当前页面内与成功返回的成果关联；离开页面或切换项目后不保留。历史成果或响应丢失后找回的成果无法从服务端恢复输入，须使用生成时另行保存的输入。表单“保存当前输入 JSON”只保存当前编辑器内容，不保证与所选历史成果一致。使用安装了 attachments extra 的同一发行版（只需本地 Python，无数据库或模型）：

```powershell
cd agent
uv run --frozen --extra attachments python -m minimax_code.office_xlsx verify 'C:\exports\清单.xlsx' --spec 'C:\exports\office-input.json'
```

CLI 完整重验包及全部单元格，输出报告 JSON，成功 exit 0；失败固定脱敏信息且非零退出。将 file_sha256/input_sha256 和其余固定报告字段与下载报告比较。输入规范化包括空串变空白；SHA-256 对应规范输入 JSON，不是原 JSON 文件排版字节。命令不会连接服务、执行生成、迁移数据库或调用模型。

## 聊天中的汇总和图表

普通聊天可要求 Agent 调用 `generate_table_xlsx` 的可选 `summaries` 与 `chart`。例如在原有 `spec` 之外添加：

```json
{"summaries":[{"column":"数量","operation":"sum"},{"column":"数量","operation":"count"},{"column":"数量","operation":"average","decimals":2}],"chart":{"kind":"bar","category_column":"名称","value_column":"数量","title":"数量比较"}}
```

`count` 统计非空值（包含 0 和 false）；`sum`、`average` 仅接受数字列，忽略空值；全空的 sum 为 0，平均值为空。average 默认保留 2 位，可选 0–8 位，采用十进制四舍五入（中点远离零）。计算值直接写入新增的“汇总项目”“汇总值”列，**不是公式**，修改原数据不会自动重算汇总。汇总最多 20 项，输入最多 18 列，最终工作表仍遵守 1000 行及 5000 格上限；精度或范围无法安全表示时拒绝。

`chart` 支持 `bar` 或 `line`，类别引用已有文本/数字列，数值引用已有数字列，图表只引用原始数据行，不含汇总行。新生成的带图表 XLSX 登记为办公成果，可下载后在 Excel 中查看；预览仅显示存储单元格，不呈现图表。受限 worker 按 `xlsx_chart_values_v1` 核对存储单元格及图表系列引用，不代表纯表格结构、图表视觉或业务验收。旧版独立图表附件仍可从项目附件访问，不自动补登记；上传的图表文件不自动获得生成校验回执。

办公成果面板提供“静态汇总和图表”配置，使用当前 JSON 表格的列；CSV 草稿编辑后需先明确转换。汇总及图表成果均登记在办公成果，可以关联符合既有约束的 run。同一请求键与相同输入可安全重试，不同输入使用同一键会冲突；明确生成新版本需使用新键。输入快照只在当前页面保留，图表输入包含配置及原始数据行数。


## 双表完整对账

聊天的表格任务模板可选择“双方完整对账”，或要求 `join_spreadsheets_xlsx` 使用 `join_mode: "reconciliation"`。成果先列出全部左表行，再按右表原顺序追加未匹配的右表行；新增 `关联状态` 列分别标记 `matched`、`left_only` 和 `right_only`。右侧独有行的键填入对应左侧键列，其他左侧字段为空。空键不会匹配，默认情况下右表完整键重复会拒绝生成；左表重复键仍保留各行，因此匹配行数不是唯一键数。已有输出列不能叫 `关联状态`，须先重命名。结果仍受 20 列、1000 行及 5000 单元格限制，超限会拒绝而不是截断。

回执记录双方原件、哈希、键和各类行数，沿用既有权限、项目绑定及请求键规则。此模式使用版本 6 的处理说明，旧程序可能无法读取包含该回执的备份；升级前保留备份。结果不判断业务差异，也不证明键或数据正确；须人工核对。本功能尚未运行验证。

## 从项目 CSV 附件生成表格

先在项目附件中上传 CSV，再在普通聊天中提供附件名称或 ID、所需列顺序、输出列名和类型。例如：“把项目附件 data.csv 的数量列转成数字、名称列保留文本，按数量求和并生成柱形图。”Agent 可用 `generate_xlsx_from_csv` 读取并核对当前会话项目中的附件原始字节；不会只用 64 KiB 预览，也不会修改原件。工具返回来源附件 ID 和 SHA-256。调用受现有 XLSX 写入规则和规划模式约束，默认请求确认，不能跨项目选择附件。

CSV 必须为 UTF-8，可带 BOM，逗号分隔且第一行是唯一列名；原件最多 1 MiB、1000 数据行、100 个源列，最多选择 20 个不同源列，选中单元格最多 4096 字符；各行宽度必须相同。使用来源列名精确匹配，输出列可重命名和重排；空字符串转为空白。`text` 原样保存，包括以 `=` 开头的内容；`number` 接受十进制数（可带指数），不接受逗号分组、百分号、NaN 或超出 XLSX 安全精度/范围的值，保留前导零的编号应选 `text`；`boolean` 仅接受忽略大小写和两端空格的 true/false。无效编码、表头、行宽或类型转换均失败，不登记结果。最终表格及静态汇总仍受上文 XLSX 行数、格数和精度限制。

可选汇总与图表使用**输出列名**，规则和交付位置见上一节；图表及无图表成果均可使用相同请求键及输入重试。来源 ID 和哈希是工具结果中的来源记录，不意味着业务、表格内容或图表视觉已核验。从 XLSX 附件导入见下一节；不能把有界预览当成完整读取或公式计算。


## 从项目 XLSX 附件处理工作表

办公成果的「从项目 XLSX 读取表格」会先读取完整工作表名称及可见状态（最多 32 张），不依赖可能截断的附件单元格预览。隐藏表显示但不能选择；可见表仍须通过完整提取的格式限制，列表不代表其内容可用。解析失败时显示错误，不把失败当成空工作簿。此界面接入尚未运行验证。

普通聊天可用 `generate_xlsx_from_xlsx`，提供当前项目附件 ID、源工作表的准确名称、输出文件名、输出工作表名和所选列。模型可重排列、重命名列，按上节规则转换为 `text`、`number`、`boolean`，并使用可选静态汇总或柱形/折线图。工具从 vault 校验完整原件大小和 SHA-256，经固定受限子进程完整读取指定工作表的存储单元格；不会读取预览后截断的数据，也不修改原文件。首行须为非空且无重复的列名，空单元格变空白。数据按存储行列读取，原来的样式、列宽、图表等不复制。

输入原件最多 2 MiB，指定可见表的数据须位于 A1:T1001，矩形范围最多 5000 格，提取文本最多 1 MiB；最终输出还受常规 XLSX 和汇总限制。为避免漏掉数据或误用缓存，含公式（包括有缓存的公式）、错误单元格、合并单元格、隐藏行列、筛选、图表或其他复杂工作表功能的表会拒绝。常见日期格式按工作簿 1900/1904 日期系统转换为 ISO 日期或无时区时间文本，目标列须选 `text`；1900 系统的虚构 1900-02-29（序号 60）、无法安全转换或不明确的日期/时间格式拒绝。日期转换保留到毫秒，超过可安全判定的精度会拒绝；无日期格式的普通数值保持数值，不猜测是否为日期。常见百分比、货币、小数和科学计数格式输出**底层数值**而非显示文本，例如 25% 导出为 0.25；货币符号、百分号和显示小数位不保留。结果返回已识别的日期、百分比和货币源列，未进行汇率或业务核验。`000000` 等零填充编号和不能可靠识别的自定义格式拒绝，以免丢失显示含义。请在副本中检查结果，把公式替换为**已核实的值**、取消隐藏/合并和筛选，必要时将编号和复杂日期转为文本，再重新上传。处理结果不计算公式或校验业务、事实和视觉。

成功结果附带源附件 ID、SHA-256 和工作表名。成果使用会话、来源及请求键实现相同输入重试，图表也登记在办公成果。解析器拒绝外链、宏及不安全容器；资源门不可用或超时时拒绝，不回退为预览导入。


## 按页或正文段落读取附件

同一工具也可读取 UTF-8 TXT 或 CSV 原件，`unit` 固定为 1，`offset` 和返回的 `next_cursor` 按 Unicode 字符计数，每次最多 4000 字符，可继续读取截断预览之后的内容，直至 `next_cursor` 为 null。空文件返回 `empty`；非 UTF-8、含 NUL 或游标越界时拒绝。CSV 返回原始文本，不解析记录、不计算公式，也不保证 CSV 结构有效。此功能沿用项目及会话绑定、原件完整性核验和只读权限；附件内容是不可信数据，不是指令。

普通聊天可使用 `list_project_attachments` 找到当前项目中的 PDF 或 DOCX 附件，再调用 `read_project_document`。工具读取并核验完整 vault 原件，不使用截断的 64 KiB 预览；不接收项目 ID。PDF 的 `unit` 是从 1 开始的物理页，DOCX 的 `unit` 是正文与表格中按顺序出现的非空字符串段落序号。默认从 `unit=1, offset=0` 开始，每次返回该页或段中最多 4000 个字符，并提供字符起止、总页/段数、位置标签与 `next_cursor`；长页/段要跟随返回游标继续读取，不能跳到下一页而遗漏余文。空页/文档明确标记 `empty`，无文字不代表没有图像内容。

普通聊天的 `generate_report_docx`、`generate_report_pdf` 和 `generate_report_pair` 支持可选的 `document_excerpts`，将已读取的项目附件位置纳入报告，正文可按顺序引用 `[资料1]`、`[资料2]`。每项提供 `attachment_id`、`expected_sha256`、`unit`、`start`、`end`；字符范围是同一页或段内的半开区间 `[start, end)`，最多 1000 字符，最多 10 项。先用列表获取身份并用 `read_project_document` 确认位置；生成时服务再次读取原件并核对哈希和范围，不接受调用者自填摘录。报告附录列出原始文件名、附件 ID、SHA-256、页或段位置、字符范围、提取范围与 OCR 状态，并标明仅为选定摘录、事实未经核验。PDF 只提取已有文字，DOCX 仅覆盖正文和表格段落；OCR 不自动执行，空白页不等于没有图像内容，不能把摘录当作全文。摘录受报告已有段落、块和总文本上限约束；超限时需缩小范围或分份生成。报告附录记录的是生成时读取的内容，不能替代人工核验引用与结论的关系。

普通 Native 项目会话也可要求将已登记的 UTF-8 TXT 附件转换为 DOCX、PDF 或两者：Agent 使用 `generate_report_from_text`，以附件 ID 和 SHA-256 读取原件，提供报告标题和新文件名，在项目附件中保存新成果并关联运行。文本不经模型重新转述，按每 4096 字符拆分段落，UTF-8 BOM 被移除；文本按纯文本排版，不解析 Markdown。受现有报告文本和段落上限约束，超限报错而不截断。原件不修改；两种格式分别保存，结果不明确时先查看附件再重试缺失格式。转换不代表事实或版式已核验；此入口尚未执行验证。

`search_project_document` 可在当前项目的 PDF、DOCX、UTF-8 TXT 或 CSV 原件中定位区分大小写的字面关键词。提供附件 ID、列表中的 SHA-256 和 1–128 字符的查询，从 `unit=1, offset=0` 开始，使用同一查询和 SHA-256 跟随 `next_cursor` 直到为空。每次至多扫描两个有界片段、返回 20 个匹配；片段分页边界的匹配会被检出，但不会跨 PDF 物理页或 DOCX 段落拼接。结果给出可供 `read_project_document` 使用的位置及短片段；失败时返回已找到的匹配和未完成的续扫位置。单次无结果不代表全文无匹配，搜索完成也仅代表已覆盖当前游标之后的可提取范围；PDF 不做 OCR，DOCX 不覆盖页眉页脚、批注、修订、文本框或图像。文档内容是不可信数据。

聊天可先用 `list_project_xlsx_sheets`，从附件列表提供 ID 和 SHA-256，获取最多 32 个工作表的完整名称及 visible、hidden 或 veryHidden 状态。该工具仅返回元数据，不返回行、不计算公式；表名是不可信数据，表是否可读取仍为未知，隐藏表不能作为可见表读取。原件限 2 MiB，包结构不支持或超出解析限制时明确失败，不能把失败视为零张表。然后用 `read_project_xlsx_sheet` 只读分页查看当前项目的 XLSX：指定准确的可见工作表名，从 `row_offset=0` 开始跟随 `next_row_offset`；每页最多 50 行、行数据的 JSON 最多 16 KiB，单行超限时明确报错，不跳过该行。它复用完整工作表导入的解析边界（原件最多 2 MiB、A1:T1001、5000 格及 1 MiB 提取文本），每页会重新解析原件并核对会话项目绑定。公式、隐藏行列、合并单元格和其他不支持的结构会拒绝读取，不能据此推断已读完或已计算；日期转换为 ISO 文本，百分比和货币保留底层数值，业务值未核验。

该功能仅提取已有文字，PDF 不重建版式或表格；DOCX 不包含页眉、页脚、批注、脚注、修订、文本框或图片中文字。均不执行 OCR；返回文本和文件名均为不可信数据，不是操作指令。原件上限 10 MiB，PDF 最多 200 页，DOCX 最多 10000 个有文字的正文段落，单页或段文本最多 1 MiB 字符；解析复用资源受限子进程，超时、不支持的容器及缺依赖时拒绝，不能当作已读完。功能保留规划模式下的只读使用，受现有受限执行规则约束。


### 按条件提取表格记录

在聊天中可要求从项目 CSV 或 XLSX 附件按字段筛选后生成新表，例如“从台账中筛选状态为已完成、金额大于等于 100 的记录，再汇总金额”。`generate_xlsx_from_csv` 和 `generate_xlsx_from_xlsx` 接受最多 10 条 `filters`，每条包含输出列名 `column`、运算符 `operator` 和与输出列类型一致的 `value`。多个条件同时满足；`eq`/`ne` 为等于/不等于，`gt`/`gte`/`lt`/`lte` 为大于/大于等于/小于/小于等于。文本区分大小写，顺序比较按 Unicode 字符顺序；数字按转换后的数值比较，布尔值只支持等于和不等于。空白可用 `null` 的等于或不等于筛选，空白不参与顺序比较。

读取和类型检查覆盖完整来源，筛选发生在转换后、汇总与图表之前；来源中的无效数据不会因被筛除而忽略。结果包含条件、来源行数和匹配行数；这些信息是处理记录，不代表业务核验。零匹配可生成空数据表，但图表或汇总可能因自身限制被拒绝。原附件保持不变；来源哈希、项目会话绑定和写入权限沿用既有导入流程。


## 聊天中按类别汇总附件

在项目附件上传 CSV 或符合上一节约束的 XLSX 后，可以在普通聊天中提出例如“按类别统计每类记录数、金额合计和平均金额，生成新表”。`generate_xlsx_from_csv` 和 `generate_xlsx_from_xlsx` 接受可选 `group_by`：`column` 为选中后的输出列名，`metrics` 为 1–18 项，每项指定输出列名 `name`、来源输出列名 `column`、`operation`（`sum`、`count`、`average`），平均值可指定 `decimals`（0–8，默认 2）。输出为分类列、`行数`和各指标列；名称须互不重复。可在分组后以结果列绘图，但不能同时请求旧的 `summaries`。

先完整检查并转换来源、按所有筛选条件筛选，再按转换后的值精确分组；文本区分大小写、不自动去空格，空白分类合为一组，组按首次出现的顺序排列。`行数`包含该组所有匹配行，`count` 统计指定列的非空值（包含 0 和 false）。`sum` 和 `average` 只接受数值列并忽略空值；全空时两者均输出空白，避免将缺失数据当作零。数值先按十进制计算，平均值按指定小数位四舍五入（中点远离零）；超出 XLSX 安全精度或范围则拒绝。零匹配产生仅含表头的表；图表仍受原有非空和类型限制。结果是静态值，不会随原件变化而重算。

工具返回筛选条件、来源行数、匹配行数、分组参数及组数；来源 ID、哈希和 XLSX 源表信息沿用现有流程。输入和结果仍受现有行数、单元格、类型和大小限制；XLSX 日期、百分比及货币仍按上节口径处理，不推断单位或币种。成果在办公成果中按请求键规则生成；同一键用于不同输入会被拒绝。原件不修改；存储值检查不代表计算口径适合业务、来源正确或渲染已核验。此新增分组功能尚未运行验证。


## 聊天中排序附件结果

普通聊天可要求将项目 CSV 或受支持的 XLSX 附件生成的新表按字段排序，例如“筛选已完成记录，按金额从高到低、名称从低到高排列”。`generate_xlsx_from_csv` 和 `generate_xlsx_from_xlsx` 的可选 `sort_by` 是 1–3 项数组，每项包含准确的输出列名 `column` 和方向 `direction`（`asc` 或 `desc`），列名不可重复。依次按数组顺序确定主次键；排序稳定，所有键相等时保留排序前顺序。先转换并筛选，再按需分组，随后排序，最后生成汇总和图表；分组时排序列须为分组结果列名。

数字按转换后的数值排序，文本按区分大小写的 Unicode 字符顺序排序，布尔值升序为 false、true；降序反转非空值顺序。每个排序键的空白无论升降序均排在该键非空值之后。日期属于文本，只按文本顺序比较，不解析或推断日期；只有一致的 ISO 表示才能按此顺序进行合理的日期比较。输出仍受既有输入和 XLSX 行数、单元格数及大小限制，排序不会增加输出行。结果返回排序配置和原有来源信息，原附件不修改；存储值检查不表示排序口径或业务数据已核验。此新增排序功能尚未运行验证。


## 聊天中清洗表格字段

对于项目 CSV 或受支持的 XLSX 附件，聊天中可以要求“去掉名称两端的空白，把金额列的 N/A 和 - 当作缺失值，再按名称去重并汇总金额”。两个导入工具的 `columns` 每项都可显式设置 `trim: true` 和 `null_values: ["N/A", "-"]`；未指定时不做这两项清洗。`trim` 去除单元格两端的 Unicode 空白，不改变中间空白；随后用区分大小写的完整文本精确匹配空值标记，匹配则转为空白。每列最多 20 个不重复标记，每个最多 4096 字符；标记本身不会自动修剪。先完成清洗，再按所选类型转换、计算、筛选、去重、分组、排序和汇总。清洗适用于文本、数字和布尔列，未列为标记的非法数字或布尔值仍会使整个请求失败，不会被静默跳过。

结果返回各输出列的清洗设置和 `changed_cells`：统计清洗前后原始文本不同的单元格数，按来源全部数据行统计，且在筛选和去重之前；空字符串本来就转为空白，不计为变化。清洗可能合并原本不同的去重键或分组，且标记会丢失原文本，应先确认口径。清洗后结果通过办公成果交付，原件不覆盖，来源哈希及会话项目和权限限制不变。CSV/XLSX 导入成果会在办公成果的校验报告中保存处理说明，可在成果面板展开查看或下载校验报告。说明包含来源附件 ID、哈希及源工作表、列映射和类型、清洗及变化计数、计算、筛选、去重、分组、排序、汇总配置及各阶段行数；输出行数为添加静态汇总之前的行数。报告（含说明）总长最多 64 KiB，超限时生成会失败。说明记录的是处理口径而非业务核验，筛选值和空值标记也会持久保存，应避免在这些参数中放入不必要的秘密。处理说明与成果在同一登记事务中保存，并参与新成果的请求键冲突判定；启用此功能前已有成果的同键重试仍返回原成果，不会补造历史说明。聊天导入生成的图表成果的说明也随办公成果持久登记；此前生成的图表附件不会自动补登记。业务正确性与渲染仍需人工核验。本功能尚未运行验证。

## 聊天中按字段去重附件记录

`generate_xlsx_from_csv` 和 `generate_xlsx_from_xlsx` 可选 `deduplicate_by`，例如 `["编号", "日期"]`。它接受 1–20 个互不重复的准确输出列名，按转换后的字段组合精确比较，保留来源顺序中的第一条记录；其余字段即使不同也会被删除。文本区分大小写，不自动去除空格，空白与空白相同；数字、布尔值按转换后的值比较。日期文本不做额外解析，去重不会推断相似名称或业务含义。

处理顺序是完整读取与类型转换、筛选、去重、分组、排序，最后生成汇总或图表。先筛选意味着保留的是匹配记录中的第一条；分组统计仅包含去重后保留的记录。结果包含筛选匹配行数、`deduplicate_by` 和 `removed_duplicate_count`，以及既有来源信息；用户应自行确认去重键和保留规则适合业务。原附件不修改，既有权限、项目绑定、来源限制和成果重试规则仍适用。此功能尚未运行验证。

## 聊天中计算比率

CSV 和 XLSX 导入工具的 `calculated_column` 支持 `operation: "divide"`，例如以数值列 `金额` 除以 `数量`，将结果写入名为 `单价` 的新列。`left` 为被除数，`right` 为除数，均须是已选择的数值输出列；新列名须与其他输出列不同。`decimals` 为 0–8 的整数，默认 2，按十进制四舍五入（中点远离零），结果为静态数值而非公式，也不自动转换为百分比或推断单位。加、减、乘仍按原有精确计算口径，`decimals` 不影响它们。

任一操作数为空时结果为空；两者均非空而除数为零时整个请求失败。计算在筛选之前对完整来源进行，因此即使该行随后会被筛除，也不能忽略零除数。超出安全数值表示范围时拒绝生成。两种来源均保留原附件，生成独立成果；成果的持久处理说明记录除法配置及实际小数位，并参与既有请求键冲突判定。业务口径和来源值需由用户核验；此新增能力尚未运行验证。

## 报告表格位置编辑

结构化报告的可视编辑器支持在指定行或列之前插入空白、删除指定行或列，以及上下移动行或左右移动列。编辑只作用于报告草稿，保留至少一行一列及每表最多 100 行、20 列的限制；PDF 仍有独立大小限制。若启用跨页重复表头，当前第一行即表头，插入、删除或移动首行后应重新核对。原附件不受影响；生成后的内容和版式仍需人工核验。此功能尚未运行验证。

普通正文可以逐行复制到选定的结构化章节末尾，便于将已有附件摘录整理为章节并与表格组合。复制保留空行、原正文及已有章节；多次操作会重复追加。章节内容无法无损编辑，或复制后超过内容块、单段文字及大小限制时不会修改草稿。带编号的引用需重新核对；复制不会核验事实或生成文件。此功能尚未运行验证。

## 聊天中连续计算多个表格字段

CSV 和 XLSX 导入工具可使用 `calculated_columns` 指定 1–10 个按顺序执行的计算，格式与原有 `calculated_column` 一致；两种参数不能同时提供。每项 `name` 是新列名，`left`、`right` 引用已经选择的数值列或前面步骤产生的数值列，不能引用尚未计算的列。比如依次计算数量乘单价得到金额、金额乘税率得到税额，再将金额加税额得到含税金额。源数据必须提供税率等操作数，工具不自动推断税率、币种或单位。输出列名必须唯一，总列数和单元格数仍受原有表格限制。

所有计算在筛选、去重、分组、排序和汇总之前对完整来源执行：任一行的无效操作、零除数或不能安全存储的结果会使整个请求失败，即使该行之后本会被筛除。空操作数产生空结果，并可传递至后续计算。加减乘使用十进制计算；除法按 `decimals`（0–8，默认 2）四舍五入，中点远离零，后续步骤使用已经舍入并存储的结果。结果是静态值而非公式，修改数据不会重算。来源附件和原件保持不变；会话项目绑定、写入权限、请求键冲突及来源哈希规则沿用原导入流程。成果校验报告持久保存有序计算配置，与输出一起参与同键冲突判断；旧单列处理说明继续可读。计算口径及业务结果仍需人工核验。本功能尚未运行验证。


## 聊天中按多个字段联合汇总

对 CSV 或受支持的 XLSX，可按部门和月份等字段组合汇总，例如 `group_by: {"columns": ["部门", "月份"], "metrics": [{"column": "金额", "name": "金额合计", "operation": "sum"}]}`。`columns` 为 1–18 个按输出顺序排列、互不重复的精确输出列名；原有单字段 `column` 仍受支持，两种写法须且只能选一种。分组字段、自动生成的 `行数` 与指标列合计最多 20 列，输出列名须符合既有唯一性规则。字段不存在、重复或类型不符时请求失败。

各字段转换后的值组成联合键，只有整个组合相同才归为一组；空白在对应字段中与空白相等，不会把不同部门或月份合并。分组按首次出现的组合排列，分组字段按指定顺序输出。筛选、去重、分组和排序的顺序，以及指标的空值和舍入口径与单字段分组一致。排序可引用分组结果列。处理说明保存原始分组配置，参与同键冲突判断；原件不覆盖，结果为静态值。此能力尚未运行验证，业务口径和结果仍需核对。

## 两份表格的精确关联

普通聊天可使用 `join_spreadsheets_xlsx` 将当前项目中的两份 CSV 或 XLSX 附件精确左关联，例如以项目编号和日期从第二份表补充名称。分别指定附件 ID、选中的列和关联键；每侧使用单列 `key` 或有序列名数组 `keys`（1–20 列），两者互斥。两个键列表长度相同，按顺序逐项对应；可以分别使用不同列名。原有单列 `key` 调用保持兼容。XLSX 还必须指定准确的可见工作表名。每份来源均沿用前述大小、行列数、数据类型、清洗和 XLSX 解析限制。选择右表所有键列之外至少一个字段，输出列名须互不冲突，输出仍受 20 列、1000 行和 5000 单元格上限约束。

两侧对应键列必须为同一种类型；文本区分大小写，只有显式指定的 `trim` 和 `null_values` 会清洗。任一键分量为空的行不匹配，右表重复的完整非空键组合使请求失败，左表重复组合允许并分别匹配；右表不完整的键组合即使重复也不会匹配或导致重复键错误。默认输出保留左表全部行及顺序，找不到的字段为空，匹配成功但源字段为空也保持为空；结果报告实际键、匹配、未匹配及右侧含空键分量的行数。编号可能有前导零时应选文本，避免数值转换丢失信息。不会修改原附件或推断缺失内容。

可选 `join_mode` 为 `matched` 或 `unmatched`，分别只输出匹配成功的左表行或未匹配的左表行，便于生成对账清单；默认 `left` 输出全部左表行。输出保持左表原有顺序，未匹配结果的右侧字段为空，键含空值的左表行也归为未匹配。两侧原件均先完整读取和类型校验，默认情况下右侧重复完整键仍会拒绝；零行结果保留表头。返回的匹配及未匹配计数针对完整左表，`output_rows` 为实际输出行数。

`right_unmatched` 生成右表存在而左表没有完整匹配键的记录，按右表原顺序输出。右侧键值放入对应的左侧键列，其他左表列为空，右侧所选非键字段照常输出；右侧含空键的记录也归为未匹配，即使左侧同样含空键。左表重复键不影响判断，右表重复完整键仍拒绝。回执的 `right_unmatched_rows` 是右表未匹配行数，原有匹配和未匹配计数仍按左表计算。此模式使用 v5 处理说明，旧版程序可能无法读取含此回执的备份；原件不变，结果和业务口径需人工核对。该功能尚未运行验证。

交付回执保存两份原件 ID、SHA-256、工作表、列选择和清洗计数、实际有序键与关联计数。单键旧接口继续使用 v2 处理说明；使用数组键时使用 v3；`matched` 和 `unmatched` 使用含模式与数组键的 v4。旧版程序可能无法读取含 v3 或 v4 回执的备份，升级前应保留备份。同一个会话的关联请求键只能用于相同输入和输出参数，安全重试使用相同键；修改后须使用新键。生成受已有写文件、表格生成、CSV 导入、XLSX 导入及本工具权限规则共同约束。关联结果的业务正确性与呈现仍须人工核对；当前实现尚未进行本次验证。


## 聊天中填充缺失值

`generate_xlsx_from_csv` 和 `generate_xlsx_from_xlsx` 可选 `fill_missing`，例如 `[{"column":"地区","value":"未知"},{"column":"数量","value":0}]`。最多指定 20 个不重复的已选择输出列；每项的非空常量必须符合列的文本、数字或布尔类型及原有 XLSX 安全范围，不能填 `null` 或空字符串。仅替换转换后的空白，包括显式空值标记；不会替换 0、false 或非空文本。填充在清洗、类型转换之后和全部计算、筛选、去重、分组、排序、汇总及图表之前进行，所有来源行参与，包括随后被筛掉的行。非法类型或范围使整个请求失败，即使没有空白或来源没有数据行。

工具返回每列的填充值和 `filled_cells`，处理说明将同样的信息与来源附件 ID、哈希和工作表一起持久登记，并参与同键输入冲突判断；相同来源、请求键及输入可安全重试，改动填充值须使用新键。原件不覆盖，输出为静态值。填充会影响后续计算和分组，填充值可能包含敏感信息；业务口径仍须人工确认。旧版程序可能无法读取包含该字段的处理说明，升级前保留备份。本功能尚未运行验证。

### 对已有办公成果继续处理

聊天的“表格任务工作流”可选择“已有办公成果”，读取当前项目成果列表并明确选择一个成果，填写准确的可见工作表名和处理目标。准备时重新核对成果、附件、项目、当前会话及服务身份，生成携带成果 ID、附件 ID、SHA-256 和服务 ID 的聊天草稿；需要用户检查并发送，界面不会自动执行。用户仍需确认表头、字段类型和筛选、汇总口径，尤其要注意来源中已有的静态汇总行可能被当成普通数据再次汇总。

办公表格草稿支持按最多三个不同列依次排序；前一个键相同时比较下一个键，每个键可选文本或数字及升序或降序。空字符串始终排在对应键的最后，所有键相同的行保持原顺序。文本按 UTF-16 码元比较，区分大小写且不去空白；数字排序先对完整列按安全精度规则校验，任何无效值会拒绝整次操作。可预览前五行并应用，排序可撤销；导入原件不修改，生成 XLSX 后得到静态结果。列名或结构变化会重置排序条件，处理口径和业务结果需自行核对。此功能尚未运行验证。


## 文本匹配与分组最值

聊天导入 CSV 或 XLSX 时，筛选条件还可使用 `in` 或 `not_in`，例如 `{"column":"部门","operator":"in","value":["设计部","工程部"]}`，一次选出两个部门并生成新成果。列表须包含 1–20 个与目标列类型一致的值；文本精确匹配且区分大小写，数字和布尔按类型匹配。`null` 代表空白，`in` 仅在列表包含 `null` 时匹配空白，`not_in` 则在列表不包含 `null` 时保留空白。多个筛选条件仍须同时满足；筛选在计算之后、去重和分组之前执行。筛选配置保存在成果处理说明并参与请求键冲突检查；来源原件不变。结果和业务口径仍需核对，本功能尚未运行验证。

聊天中的 `generate_xlsx_from_csv` 和 `generate_xlsx_from_xlsx` 支持在 `filters` 中对文本输出列使用 `contains`（包含）、`not_contains`（不包含）、`starts_with`（开头匹配）和 `ends_with`（结尾匹配）。例如 `[{"column":"客户名称","operator":"contains","value":"科技"}]`。匹配区分大小写，按转换后的完整文本逐字比较，不自动去空格或使用正则；匹配值必须为非空字符串。空白单元格不匹配这四种条件，包括 `not_contains`；要选空白须用 `eq` 和 `null`。多条件仍为同时满足。

分组的数字指标 `group_by.metrics` 可使用 `min` 和 `max`，例如 `{"column":"金额","name":"最高金额","operation":"max"}`。它们仅接受数字列，忽略空白；组内全为空时输出空白，零是有效数值。结果是静态值，可继续排序、生成图表或作为新 XLSX 成果交付。完整输入先经过类型校验，筛选与去重后再分组；来源附件不修改。处理说明记录筛选和分组配置，与既有成果请求键冲突规则一致。业务口径和结果仍需人工核对；本次改动未运行验证。


### 附件交叉汇总（未验证）

普通聊天可要求“按地区列出各季度金额合计”，指定项目中的 CSV 或受支持 XLSX 附件、列名、每个季度的具体值和输出列名。`generate_xlsx_from_csv` 与 `generate_xlsx_from_xlsx` 的 `pivot_by` 在筛选和去重后生成静态交叉表：`row_column` 为行字段，`category_column` 为分类字段，`value_column` 为统计字段，`operation` 可为 `count`、`sum` 或 `average`；`buckets` 按输出顺序列出 1–19 个 `{name, value}`，例如 `[{"name":"一季度","value":"Q1"},{"name":"二季度","value":"Q2"}]`。类型必须与分类列一致，`null` 代表空白。未列出的分类会使请求失败，避免静默丢失记录；要排除分类应先明确筛选。
