# 40 项评测：固定输入与独立制品检查（建设中）

本目录与 `../run_eval.py` 的六项 pilot 独立。清单是 20 编程、10 办公研究、5 远程恢复、5 自动化。**当前 35 项可准备和独立检查：20 编程、10 办公、0 远程、5 自动化；其余 5 项 `not_ready`**，没有固定输入和检查器，禁止运行或计作通过。编程题是小型、受控的代码维护场景，尚不代表完整仓库级任务难度。办公任务以固定的合成资料和结构化结果为验收对象，不能证明真实外网来源检索或 Word/PPT 成品质量；自动化任务检查决策逻辑，不能证明真实调度执行。各任务的 `REQUEST.md` 是任务输入；`checks/` 是独立于任务工作区的验收器。

本工具**不启动产品、模型、远程服务或自动化任务**，不收集运行回执、预算、用量或人工介入；只准备固定输入并检查制品。`artifact_status=passed` 仅说明独立检查通过，不能当作真实执行成功或总体通过。`execution_status=not_recorded`、`budget_status=not_recorded`、`delivery_status=not_proven` 会始终明确保留。正式评测还需要安全的真实执行适配、终态与后代清理证据、预算账本、成本与人工介入记录、独立评审及跨轮结果汇总；现有 pilot 的核算规则见 [评测计量](../../docs/evaluation-accounting.md)。

## 准备、检查、留证

从仓库根目录运行，下面仅示范一次本地制品检查，不调用模型：

```powershell
python evals/real40/runner.py status
python evals/real40/runner.py prepare code-01 D:/eval-work/round1/code-01
# 在隔离工作区完成 REQUEST.md 后，再检查制品
python evals/real40/runner.py verify code-01 D:/eval-work/round1/code-01 --round 1 --record D:/eval-records/code-01-round1.json
python -m unittest discover -s evals/real40 -p test_runner.py -v
```

`prepare` 拒绝已有目录；每次任务、每轮均应使用全新目录。`verify` 拒绝覆盖已有记录，只接受 1、2、3 轮；保存固定输入、独立检查器与候选工作区的 SHA-256、检查输出及退出码，并拒绝改动指定的只读输入。验证时工作区变化会失败。输出退出码 0 表示制品检查通过、1 表示失败或超时、2 表示输入/环境错误。检查器直接运行候选 Python 代码：`-I` 和 15 秒超时不是安全沙箱；**仅在可信代码或经独立隔离的环境中执行**，不把此命令用于不受信任代码。不要同时有其他进程写入工作区。

`status` 显示任务准备状态与三列 `not_run` 初始模板；它不读取任意外部结果记录，不是成绩汇总。实际运行三轮时，应分别保留不可覆盖的记录文件、产品回执和预算证据；比较各轮的输入和检查器哈希，不一致时不得直接汇总。尚未实现自动关联记录、收集真实运行证据或完整交付判定；不要把当前状态输出当作三轮已经执行。

单元测试使用临时目录与人为编写的示例解，覆盖初始缺陷被拒绝、示例修复通过、办公资料的缺失/正确/错误制品、边界/错误解、输入篡改和记录防覆盖。它们是检查器回归测试，**不是产品真实任务结果**。当前没有真实 40 项评测结果，所有三轮均未运行。
